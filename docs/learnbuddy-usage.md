# LearnBuddy 能力全景 × AutoGrader 开发流程融合

> 任务一交付物｜创意验证阶段｜不实现任何功能，只确立"用平台开发"的方法论
> 结论先行：本赛题的评审看三样东西 —— **可访问的在线链接、源码仓库、LearnBuddy 对话记录**。
> 其中对话记录是"AI 能力来源"的唯一合法证明。因此 LearnBuddy 不只是开发工具，它本身就是**产品的 AI 运行时**。

---

## 一、先理解规则，再谈功能：三条硬约束决定了技术路线

| 官方答复 | 出处 | 对开发的直接约束 |
|---|---|---|
| "本次赛事以腾讯 LearnBuddy 平台为载体，最终效果呈现时**最好不要包含第三方 AI**" | 李磊 | 产品里不能出现 OpenAI / Anthropic / 国产第三方大模型 API 调用，代码仓库里也不要留下相关依赖 |
| "平台本身**没有开放给网页用的 API**" | 张瑾 | 你的 Next.js 前端**无法在运行时调用 LearnBuddy**，AI 推理不能发生在用户打开网页的那一刻 |
| "初赛的作品形态是**提交 demo 即可，不用部署到正式环境**" | 王才荣 | 不需要生产级后端、数据库、鉴权、运维 |

这三条叠加起来只有一个自洽解：**AI 推理必须发生在 LearnBuddy 侧（对话中），Web 端只做确定性渲染**。
这个范式切换是整个项目的地基，详见 `docs/deliverable-strategy.md`。

补充一条风险提示：**"赛前做的壳子和设计计划不可以复用"（李磊答复星树）**。
当前仓库除 `README.md` 外，所有文件均为 0 字节空占位——实质内容尚未产生，风险很低。
但仍建议：赛程正式开始后，用 LearnBuddy 重新生成 README 与全部代码，确保每一份产物都能追溯到赛程内的对话记录。

## 二、LearnBuddy 能力全景（七层）

### L1 任务与工作模式层
- **三种工作模式**：Craft（你说我做）/ Plan（先想后做，出方案待确认）/ Ask（只分析不落地）
- **多任务并行**：任务按文件夹分组、按状态筛选、可随时续接历史任务
- **对话区**：持续追问、上传文件（PDF/docx/图片/代码）、顶部快捷操作
- **结果区四视图**：产物 / 全部文件 / 变更 / 预览

### L2 智能体能力层（AutoGrader 的灵魂所在）
- **多 Agent 自主规划协作**：一次任务可调度多个细分智能体分工配合
  → 天然对应你的 **Parser / Evidence / Grader / Reviewer / Feedback** 五 Agent 流水线
- **专家分身（Expert）**：5 步构建链路
  `ima 知识库导入 → 上传专家素材 → AI 提炼专家思维 → 专家本人校准 → 分享使用`
  → 做一个「计算机实验报告评阅专家」分身，把资深助教的评分方法论、评分尺度、语言风格注入进去
- **Skills 生态**：能力可封装为标准化技能组件，支持自定义扩展
  → 把"逐项核查评分"封装成可复用 Skill，是"校本 AI 资产沉淀"的直接体现
- **跨会话长期记忆**：记住专业方向、项目进度、历史交互
  → 记住课程、班级、Rubric 版本、教师的宽严偏好，越用越准
- **严守 AI 边界**：超出研究领域会明确说"这不在我研究领域"，不编造
  → 评阅场景的**刚需**：证据不足时必须承认"未找到证据"，而不是编造引用

### L3 记忆与知识层
- **云端画像记忆**：跨会话的用户长期档案
- **历史对话检索**：语义检索过往全部对话
- **用户级记忆** `~/.learnbuddy/MEMORY.md`：跨项目习惯
- **工作区记忆** `.learnbuddy/memory/YYYY-MM-DD.md` + `MEMORY.md`：本项目专属项目日志
  → 这就是评审最想看到的**"AI 资产持续沉淀"**的落地形态

### L4 文件与代码工程层
- 本地文件读写改、批量处理、跨格式转换
- 代码开发模式：代码生成、审查、Bug 修复、重构、陌生代码库理解
- 项目级 Web/应用开发：从需求到可运行代码

### L5 内容与呈现层
- **腾讯文档**（个人版 / 企业版）：在线文档、表格、幻灯片创建与编辑
- **PPTX 生成**：从大纲/文档生成完整演示文稿
- **本地 Office 编辑**：doc/docx/xls/xlsx/ppt/pptx 实时读写
- **Visualizer 内联可视化**：SVG 图、流程图、Chart.js 图表、交互式 HTML widget
- **多模态生成**：文生图 / 图生图 / 图生视频 / 文生 3D 模型 / 图片特效模板

### L6 部署与集成层
- **静态站点一键部署**：本地构建目录 → 云端沙箱 → 直接返回可访问 URL
  → **直接解决"提供可直接访问的在线链接"这一硬性要求**
- **GitHub 连接器**：建仓库、读写文件、提 PR、管 Issue / Release
  → **直接解决"提交完整源代码仓库链接"**
- **MCP 标准协议**：可配置外部 MCP 服务器（`~/.learnbuddy/mcp.json`）
- **腾讯生态连通**：ima 知识库、企业微信、腾讯会议、腾讯乐享、TAPD、QQ 邮箱
- **浏览器自动化**：网页抓取、表单填写、截图、点击操作

### L7 自动化与安全层
- **定时任务**：一次性和周期性（RRULE）自动化，可设生效区间
- **内容安全**：机审 / 模型 / 词库 / 人工四级过滤；专家私有数据加密封装独立存储
- **合规技能**：地图合规等内置守卫

## 四、融入开发流程：八个阶段

每一阶段都用"该用哪个 LearnBuddy 能力"来驱动，并天然产出可提交的对话记录。

### 阶段 0 · 规则对齐与立项（Ask 模式）
- **用法**：Ask 模式 + 官方文档抓取，逐条核对赛事要求，产出《约束清单》
- **产出**：`docs/constraints.md`（约束清单 + 每条的技术含义）
- **对话记录价值**：证明你在赛程内完成了规则解读，且全程以平台为载体

### 阶段 1 · 需求与 Rubric 体系设计（Plan 模式）
- **用法**：Plan 模式先出方案；用 Visualizer 画"评阅流水线图""评分维度树"；与专家分身反复对谈打磨 Rubric
- **产出**：Rubric 模板（Markdown + JSON Schema）、评分点清单（建议 8–12 项，每项含权重/证据要求/扣分梯度）
- **要点**：Rubric 的粒度直接决定后面对话记录的说服力，值得多轮打磨

### 阶段 2 · 金标准样本集构建（Craft 模式）
- **用法**：上传 10–20 份脱敏样例报告到对话，让「评阅专家」分身逐份给出**人工校准后的金标准评分**
- **产出**：`demo/sample-reports/`（样例）+ `frontend/public/results/*.json`（金标准）
- **要点**：金标准必须由人（你/指导教师）确认过，这是后面"一致性评测"的基准，也是答辩时最硬的证据

### 阶段 3 · Agent 工作流与 Prompt 设计
- **用法**：把五个 Agent 各自写成一份 prompt 规格（Markdown），再封装成 Skill
- **产出**：`backend/agents/*.md`（parser / evidence / grader / reviewer / feedback）+ `docs/prompt-design.md`
- **要点**：`backend/agents/` 下现有 5 个 `.py` 空文件，建议**改为 `.md` prompt 规格**——因为真正的执行者是 LearnBuddy，不是 Python 进程（理由见策略文档）

### 阶段 4 · 前端原型开发
- **用法**：代码开发模式；先用 Visualizer 出界面草图确认布局，再生成 Next.js + shadcn/ui 代码
- **产出**：评阅工作台 / 报告详情 / 一致性评测 / 工作流溯源 四个页面
- **要点**：先锁死数据契约（`frontend/lib/schema.ts` 的 Zod schema），再写页面

### 阶段 5 · 评阅结果生产（本项目最关键的一步）
- **用法**：**在 LearnBuddy 对话中真实跑评阅**——上传报告 → 五 Agent 流水线 → 输出符合契约的 JSON → 落盘到 `frontend/public/results/`
- **产出**：每份报告一份结构化评阅 JSON（含逐项证据、置信度、复核记录、评语）
- **要点**：这一步的对话记录就是"AI 真的会评阅"的铁证。要**一份报告一个对话**，形成完整可追溯链路

### 阶段 6 · 部署与材料交付
- **用法**：静态构建 → 一键部署拿链接；GitHub 连接器建仓、推送、发 Release
- **产出**：在线 URL、仓库 URL、README（含架构图 + 体验路径 + 对话记录索引）
- **要点**：README 要写明"AI 能力由 LearnBuddy 提供，评阅结果由平台在赛程内生成"，并附结果指纹

### 阶段 7 · 答辩与展示
- **用法**：PPTX 生成答辩稿；Visualizer 画架构与效果图；可选多模态生成演示视频
- **产出**：演示 PPT、产品架构图、1 分钟演示视频

### 贯穿全程的三条纪律
1. **每轮对话结束写工作区记忆**——项目日志本身就是"AI 资产沉淀"的展示物
2. **所有产物走结果区归档**——保证"产物/文件/变更/预览"四视图有完整痕迹
3. **关键决策留在对话里**——不要只在脑子里决定，要在对话中讨论并让 AI 输出结论，这样才进得了评审材料

## 五、一句话总结

> 把 LearnBuddy 当成 **IDE + AI 运行时 + 交付平台** 三合一：
> 用它写代码、用它跑评阅、用它部署、用它留痕。
> 你交付的不只是一个网页，而是"一个由 LearnBuddy 专家智能体真实驱动、Web 端确定性呈现、仓库可追溯"的完整闭环。
