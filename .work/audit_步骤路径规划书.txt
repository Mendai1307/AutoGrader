AutoGrader 三交付物 · 步骤路径规划书
项目：粤港澳大湾区 AI Coding 创新大赛 · 方向一「AI + 教学管理助手」→ AutoGrader
版本：v1.0　|　日期：2026-09-25　|　规划原则：只排步骤路径与依赖，不做时间规划与工期倒排
零、最终目标（冻结）
一个由 LearnBuddy 专家智能体真实驱动的计算机专业实验报告评阅系统。
--- TABLE ---
# | 交付物 | 角色 | 具体产出
一 | 专家智能体包 | 能力本体（AI 在这里跑） | Prompt + Skills + Tools + Workflow + Evaluation 五件套
二 | Web Demo 产品展示页 | 产品形态 | 在线可访问链接 + 源码仓库
三 | 评审材料包 | 佐证链 | 作品介绍 PPT / 3 分钟演示视频 / LearnBuddy 对话记录归档
--- /TABLE ---
三部分不是三个独立作品，而是同一个能力的三种呈现：能力本体（一）驱动产品界面（二），
产品界面产生可验证的痕迹（三）。三者共用同一个 ReviewResult 契约。
路径 0：前置冻结（所有后续步骤的依赖根）
路径 0 不产出功能，只冻结不变式。这五项不冻死，后面每一步都会返工。
--- TABLE ---
步骤 | 内容 | 产物 | 完成判据
0.1 | 冻结 ReviewResult 契约 | Zod schema + 契约说明文档 | 12 份既有结果全部通过 zod 校验
0.2 | 冻结 Rubric 与权重 | R1–R12 定义 + 权重序列 | 权重和 = 100；每项 maxScore 与档位系数明确
0.3 | 冻结总分口径与指纹算法 | 计算函数 + 口径说明 | 总分复算、指纹复算对 12 份样例全部相等
0.4 | 冻结目录结构与命名规范 | 目录骨架 | 三部分产物各有唯一落点，命名可被机器识别
0.5 | 建立对话归档规范 | 归档模板 + 索引表 | 每条对话可定位到：日期 / 目的 / 结论 / 产物 / 对话 ID
--- /TABLE ---
0.6 写死的核心口径（不得改写）
总分 = Σ (score / maxScore) × weight —— 不是Σ (score × weight / 100)。
原因：各评分点的 maxScore 是教师自定标度（5 / 10 / 15 / 20 不等），标度大小不影响占比，占比只由 weight 决定。
权重序列（和 = 100）：5 / 12 / 5 / 7 / 20 / 10 / 11 / 13 / 7 / 5 / 3 / 2。
路径一：专家智能体包（Prompt + Skills + Tools + Workflow + Evaluation）
1.1 Prompt 层
--- TABLE ---
步骤 | 内容 | 完成判据
1.1.1 | 角色与边界：计算机专业实验报告评阅专家；定位为教师"副驾驶"（辅助而非替代） | 对超范围请求能明确拒绝

1.1.4 | 证据纪律：无证据不得高置信；证据须为原文引用 + 可定位 | 高置信评分点 100% 带证据
1.1.5 | 输出纪律：固定骨架、少自由度、禁止自由发挥与多余叙述 | 输出中无未定义字段、无冗余散文

1.6 输出稳定性专项（对应"稳定产出合规 JSON"）
这是本路径的硬指标：不是"能产出"，而是"每次都产出合规 JSON"。
--- TABLE ---
步骤 | 手段 | 作用
S1 | JSON 骨架先行 | 先固定输出结构，再填内容，杜绝结构漂移
S2 | 少自由度 | 评分点枚举、档位系数、总分公式全部固定，模型不自行发明
S3 | 分步产出 | 解析 / 取证 / 评分 / 复核 / 评语分步生成，避免一次性长输出导致结构崩坏
S4 | 自校验自修复回路 | 产出 → 校验 → 按错误清单重试（限定轮次），仍失败则标记待人工
S5 | 异常输入兜底 | 空文件 / 超长 / 全截图 / 缺章节，均返回结构化失败而非崩溃
S6 | 评测集回归 | 任何 Prompt 或 Skill 改动都过一遍样例集 + 对抗样本集
--- /TABLE ---

五、路径依赖关系
[图片]路径 0 前置冻结   └─→ 路径一 专家智能体包          ├─→ 路径二 Web Demo（消费契约与评阅结果）          └─→ 路径三 评审材料（消费智能体与产品形态）路径 0 是所有路径的根，未冻结则后续全部返工
路径一与路径二可部分并行，但共用 ReviewResult 契约，契约改动会同时影响两者
路径三最后做，因为它的内容是前两条路径的呈现
六、明确排除（范围外）
不做时间规划、工期倒排与进度压力管理
不再考虑"备用链接"相关路径
不引入第三方模型依赖（openai / anthropic / langchain-* 等）
不做生产级后端、数据库、鉴权、多用户与成绩管理
七、一句话
先冻契约，再炼智能体，后搭界面，最后收证据。
顺序不能换：契约一动，智能体与界面同时返工；智能体不稳，界面就只能展示死数据。
