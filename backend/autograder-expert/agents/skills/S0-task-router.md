# S0 · 任务识别与路由

| 项 | 内容 |
|---|---|
| Skill ID | S0 |
| 所属 | 前置 · 两条任务链的唯一入口 |
| 对内 Agent | —（编排级，不对应单个 Agent） |
| 对外名称 | —（不作为独立步骤暴露给教师） |
| 依赖 Tool | — |

## 目标

判断教师本次要做什么，路由到「创建评分标准」（任务类型 1）或「评阅实验报告」（任务类型 2），
杜绝用错流程。

## 输入

- 教师的自然语言输入
- 是否附带报告文件
- 是否附带或指向已保存的 Rubric

## 输出

- 任务类型标记：`A｜创建评分标准` 或 `B｜评阅实验报告`
- 缺件清单，例如「判为 B，但未提供 Rubric」「判为 B，但未提供报告文件」

## 执行规则

1. **只识别、不执行**——本 Skill 不产出任何评阅内容。
2. 意图不明时**只问一句**要哪条流程，不猜、不代选。
3. 判为 B 但缺 Rubric 时，回复「先创建评分标准，或从样板库选一个」，
   **不得自行生成一份 Rubric 顶上**。
4. 判为 B 但缺报告文件时，不进入 S2。
5. 出现「帮我改进这份报告」这类学生视角的请求时，判为越界，明确拒绝并说明
   本 Expert 面向教师评阅。

## 常见失败场景

- 把「帮我看看这份报告」误判为任务类型 A。
- 把「帮我改进这份报告」当成「评阅这份报告」——改进是学生的事，不在本 Expert 职责范围内。
- 在缺 Rubric 的情况下自作主张生成一套标准，破坏「评分标准由教师定义」这条边界。

## 依赖关系

- 前置：无
- 后置：任务类型 1 → S1；任务类型 2 → S2
- 被两条任务链共同依赖
