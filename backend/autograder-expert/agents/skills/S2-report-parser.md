# S2 · 报告解析

| 项 | 内容 |
|---|---|
| Skill ID | S2 |
| 所属任务链 | 流程 B · 环 1 |
| 对内 Agent | Parser |
| 对外名称 | Report Analysis |
| 依赖 Tool | **T1 文档解析器** |

## 目标

把实验报告转成可定位、可引用的结构体，为后续取证提供原文坐标。

## 输入

- 报告文件（**docx / pdf / md / txt**）
- 或纯文本（`--stdin`）
- ⚠️ **不支持截图**：T1 无任何图像 / OCR 路径，`.png` / `.jpg` 等一律返回
  `unsupported-format` 且退出码 2。截图形式的报告**无法解析**，
  路由阶段（S0）不得声称「这个我能处理」，应直接白名单外处理。

## 输出

- 章节树
- 代码块清单
- 图表位置清单
- 每个结构单元的原文坐标（章节号 / 段落序号 / 页）
- 每个块同时给 **`rawText`（原文逐字）** 与 `text`（空白规范化）两栏——
  下游取证与引用一律用 `rawText`
- **解析失败位置清单**（含 `structure-not-recognized`：有正文但未识别到任何标题）

## 执行规则

1. **只读不改**——原文一个字都不许改写、补全或润色。
2. 每个结构单元必须带可回链坐标；无坐标者视为未解析，不得进入下游。
3. 解析不到一律报「未解析」，**不得报「缺失」**（未知优于否定）。
4. 全截图 / 无文字层的输入，输出结构化失败结果，**不硬猜内容**。
5. 解析失败的位置必须显式列出，不得静默丢弃。
6. **`structure-not-recognized` 必须向上传递**：T1 报了这条失败时，本环不得把「没有章节」
   当成「章节缺失」交给 S3，必须按**未解析**处理。
7. **DOCX 标题识别不可只认一种标记**：段落级 `w:outlineLvl` 与 `styles.xml` 的样式名
   两条路径都要走（详见 `../tools/T1-document-parser.md`）。

## 常见失败场景

- 把扫描版 PDF 的空文字层当成「学生没写这一章」。
- 代码格式混乱或图文混排时静默丢弃代码块。
- 章节标题识别错误，导致下游所有取证定位整体偏移——**这种情况不会报错，最危险**。
  （2026-09-25 实测确认发生过：T1 对三种真实 docx 全部检出 0 个标题却报 `status: ok`。）
- 把解析不全的中间结果直接交给 S3，使 S3 在缺证据的情况下误判。
- 承诺「能处理截图」而入参其实是 `.png`。
