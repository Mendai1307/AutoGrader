# S1 · Rubric 构建

| 项 | 内容 |
|---|---|
| Skill ID | S1 |
| 所属任务链 | 流程 A · 创建评分标准 |
| 对内 Agent | —（流程 A 的独立能力） |
| 对外名称 | — |
| 依赖 Tool | **T6 资产库**（样板检索）、**T5 契约校验器**（经 S5） |

## 目标

把教师脑中的评分标准转成结构化、可执行、可校验的 Rubric，并在保存前完成一致性自查。

## 输入

- 教师的自然语言描述
- 教师显式指定的评分点、maxScore、weight
- （可选）教师从样板库中选中的样板

## 输出

- Rubric 对象：评分点 × maxScore × weight × 档位描述 × 判定依据说明
- 一致性自查报告：权重和、档位互斥性、可判定性逐项结论

## 执行规则

1. **样板只作起点**：教师未确认前，样板内容一律标记为「待确认」，
   **不得当正式标准使用**。
2. 权重和必须等于 100。不等于 100 时**报错并停下**，列出差额，
   **不自行归一化、不自行补齐**。
3. 每个评分点必须过「可判定性检查」——该评分点能否从报告里找到证据支撑。
   不能判定的必须当场提示教师。
4. 档位必须互斥且穷尽；档位描述必须可判定，
   不出现「较好 / 一般 / 较差」这类不可判定的措辞。
5. **只编码、不赋值**：分数刻度与权重取值一律由教师给出，
   本 Skill 只负责结构化与自查，不代教师做价值判断。
6. 保存前必须经 S5 三重校验通过方可入库。

## 常见失败场景

- 放过「内容完整」「态度认真」这类无法从报告判定的评分点。
- 教师给出的权重和是 98，Skill 自动补齐到 100——这属于替教师赋值，越界。
- 把样板当作默认值直接落库，使「教师自定标准」退化为「AI 制定标准」。
- 档位描述留有重叠区间，导致同一份报告可同时落两档。
