## 一、评阅生产总览

执行者：SubAgent 批 `W3-ABC` —— **三批评阅执行者**。
产物：`frontend/public/results/result-sample-01.json` … `result-sample-12.json`，共 **12 份真实评阅结果**。
每份结果按契约 `ReviewResult` 固化，含逐项证据、置信度、Reviewer 复核记录、学生评语与五 Agent 流水线步骤。
验收结论：**zod 契约校验 / 总分复算 / 指纹复算 三项全部通过**。

三批的划分依据是课题（也即 rubric 主题）：批次 A 为操作系统原理（线程同步），
批次 B 为计算机网络（Socket 编程），批次 C 为数据结构与算法（排序性能对比）。

## 五、一致性评测结论（AI vs 教师金标准）

评测对象：12 份 AI 评阅 vs `demo/sample-reports/manifest.json` 中的教师金标准（`goldTotalScore` 与 `expectedItemScores`）。

| 指标 | 数值 |
|---|---|
| 总分 MAE（N = 12） | **3.05** |
| 完全一致份数 | **1 份**（`sample-07`，误差 0.0） |
| 最大偏差 | **14.0 分**（`sample-04`，差档） |
| 逐项档位命中率 | **106 / 144 = 0.7361** |
| 按难度档位平均误差 | 优 **2.00** / 良 **1.53** / 中 **0.67** / 差 **8.00** |
| 单项得分与档位系数自洽 | **144 / 144** |
| 结果指纹复算通过 | **13 / 13**（12 份结果 + 1 份契约示例） |

按难度档位的误差明细（各 3 份）：

| 难度档 | 样例 | 绝对误差 | 平均 |
|---|---|---|---|
| 优 | 01 / 05 / 09 | 1.8 / 0.8 / 3.4 | 2.00 |
| 良 | 02 / 06 / 10 | 1.4 / 2.1 / 1.1 | 1.53 |
| 中 | 03 / 07 / 11 | 0.6 / 0.0 / 1.4 | 0.67 |
| 差 | 04 / 08 / 12 | 14.0 / 7.4 / 2.6 | **8.00** |

**已知局限（如实标注，已写入 `README.md` 第八节与 `docs/testing.md`）**：
低分档（差）平均误差 **8.00** 分，是其他档位（0.67–2.00）的 4–12 倍 ——
**AI 对质量差的报告扣分力度弱于人工教师**。此外，金标准由单一人（参赛者 / 指导教师侧）确认，
**不是多教师独立双盲标注**，因此 MAE 3.05 只能说明「在这 12 份上贴合度良好」，不构成绝对基准，不足以支撑泛化结论。

## 七、数据自证口径（可独立复算）

本节所列的每一项都由**确定性代码**复算，不依赖任何 AI 推断：

| # | 自证项 | 入口 |
|---|---|---|
| 1 | 契约结构校验（zod `.strict()`） | `frontend/lib/schema.ts` `ReviewResultSchema` / `validateReviewResult()` |
| 2 | 总分口径复算 `round2(Σ(score_i / maxScore_i × weight_i))` | `verifyTotalScore()` |
| 3 | 单项档位自证 `score ≈ maxScore × levelScoreRatio` | `verifyItemScore()` |
| 4 | 结果指纹复算（SHA-256） | 算法见 `docs/contract.md` 第五节 |
| 5 | 权重合计 = 100 | `ReviewResultSchema` 的 `superRefine` |
| 6 | MAE / 命中率 / 分布 | `frontend/lib/analysis.ts`，实时驱动 `/eval` 页面 |

> 口径说明：`docs/contract.md` 第五节如实标注 —— 前端目前**只展示**已固化的 `resultFingerprint`，
> 尚无浏览器端 Web Crypto 复算与完整 JSON 下载入口；页面上已落地的是**构建期**的契约口径自证
> （`/report/[id]` 分数面板的「单项档位自证」与「口径复算」）。
