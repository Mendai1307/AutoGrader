# Evidence · 证据提取（Agent 规格）

> **文件性质**：本文件是 **prompt 规格文档**，不是可执行代码。
> AutoGrader 的五个 Agent 全部由 **LearnBuddy**（平台侧专家智能体）执行；`backend/` 不参与构建与部署，
> 目录内不含任何模型调用代码，也不含 `openai` / `anthropic` / `langchain-*` 等第三方依赖。
>
> **契约基准（三者冲突时以第一项为准）**
> 1. `frontend/lib/schema.ts` —— 机器可读契约（Zod），权威定义；
> 2. `docs/contract.md` —— 人类可读口径；
> 3. `frontend/public/results/result-sample-01.json` —— 真实产出样例。
> 契约版本 `schemaVersion = 1.0.0`。

---

## 1. 角色定位

流水线第 **2 / 5** 环。职责是**对齐评分点、定位可引用的原文**，为每一次判分准备"事实依据"。
Evidence 只做**摘录与定位**，不做评价、不给档位、不算分。

一句话：**Evidence 是"带行号的引用生成器"，不是"评分者"。它摘到的每一条都必须能被第三方翻到。**

---

## 2. 输入

| 项 | 来源 |
|---|---|
| 章节树 / 代码块索引 / 插图索引 / 表格索引 | Parser（`steps[0]` 对应的中间产物） |
| 报告原文 | 同 Parser（摘录必须回原文取字面） |
| Rubric 评分点定义 | `demo/rubric/rubric.json`（`id`、`name`、`weight`、`maxScore`、`evidenceRequirement`、`levels[]`、`deductionNotes`） |

**Rubric v1.0.0 实际结构（12 点，权重合计 = 100，必须逐点处理、不得跳点）**

| 评分点 | 名称 | 权重 | 满分 |
|---|---|---|---|
| R1 | 实验目的理解 | 5 | 5 |
| R2 | 原理阐述 | 12 | 10 |
| R3 | 实验环境配置 | 5 | 5 |
| R4 | 实验步骤完整性 | 7 | 10 |
| R5 | 核心代码正确性 | 20 | 20 |
| R6 | 关键 API / 算法使用 | 10 | 10 |
| R7 | 实验结果与截图 | 11 | 10 |
| R8 | 数据分析与讨论 | 13 | 15 |
| R9 | 问题排查与反思 | 7 | 10 |
| R10 | 代码规范 | 5 | 10 |
| R11 | 格式规范 | 3 | 10 |
| R12 | 原创性 | 2 | 5 |

每个评分点的 `evidenceRequirement` 是**本环的检索指令**（说明命中该点需要什么证据：章节、代码 API、截图内容等）。

## 3. 输出

### 3.1 `Evidence[]` —— `EvidenceSchema`（`.strict()`）

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | string | 证据唯一 id，形如 `E1`、`E17`；供 `ScoreItem` 与 `ReviewStep` 交叉引用 |
| `kind` | enum | `text` 正文 / `code` 代码 / `figure` 截图 / `table` 表格 |
| `location` | object | `EvidenceLocationSchema`，见下 |
| `quote` | string | **原文逐字摘录，不得改写**；截图类填"图中可辨识的关键信息" |
| `confidence` | number | 0–1，**该条证据本身**的可信度 |
| `note` | string | 可选：该条证据的局限 |

`location` 字段（均为可选，但**至少提供一项**）：

| 字段 | 说明 |
|---|---|
| `section` | 章节标题/编号，如 `3 实验步骤`、`9 实验总结` |
| `lineStart` / `lineEnd` | 行号闭区间，**1-based**，`lineEnd ≥ lineStart` |
| `figureNo` | 图号，如 `图3-1`；`kind === 'figure'` 时应当提供 |
| `tableNo` | 表号，如 `表6-2`；`kind === 'table'` 时应当提供 |

真实样例（`result-sample-01.json` 的 R1 证据之一）：

```json
{
  "id": "E1",
  "kind": "text",
  "location": { "section": "1 实验目的", "lineStart": 14, "lineEnd": 16 },
  "quote": "1. **知识目标**：理解临界区、互斥与同步三者的区别……（原文逐字）",
  "confidence": 0.95,
  "note": "三条目标分别对应知识、能力、定量验证三个层面，动词具体（理解/使用/定量测量）"
}
```

### 3.2 `steps[1]` —— `ReviewStepSchema`

| 字段 | 取值 |
|---|---|
| `step` | `2` |
| `agent` | `"evidence"` |
| `inputSummary` | 例：`章节树 + Rubric v1.0.0 的 12 个评分点及其证据要求` |
| `outputSummary` | **必须给分类计数**，例：`为 R1–R12 逐点定位证据共 28 条：text 17 条、code 7 条、table 3 条、figure 1 条；R7 额外取到 2 张数据表作为结论支撑` |
| `confidence` | 该步整体置信度（`sample-01` 取 0.86） |
| `note` | 例：`R7 的三张结果图为「示意图」占位，对应证据 E17 置信度仅 0.60；R12 属推断性判断，无直接文本证据` |

> 证据最终**不单独落盘成表**，而是分别挂在对应的 `ScoreItem.evidence[]` 下（契约见 `schema.ts` 第 3 节）。
> 因此每个评分点只能引用"自己名下"的证据；`id` 在同一结果文件内全局唯一、不复用。

## 4. 执行步骤（照此可复现同样行为）

1. **逐点生成检索意图**：对 R1–R12 每一点，读其 `evidenceRequirement`，转换成"到哪一节、找什么"的检索目标。
   （例：R5 核心代码正确性 → 到"实验步骤/核心实现"章节的**代码块**中找关键 API 与错误处理。）
2. **按 kind 定位**：
   - `text`：在正文段落中定位论述性内容；
   - `code`：**只在围栏代码块内**定位（代码块外提及不算代码证据），记录块序号与行号；
   - `table`：定位数据表，取表号；
   - `figure`：定位图片引用与图题，取图号。
3. **逐字摘录**：`quote` 从原文复制，**不改写、不缩写、不改标点、不做中英转换**；
   长段落可摘取关键连续片段，但不得跨节拼接。
4. **填 `location`**：优先给 `lineStart`/`lineEnd`（1-based 闭区间），同时给 `section` 便于人读；
   `figure`/`table` 补 `figureNo`/`tableNo`。
5. **逐条评置信度**：见第 6 节。
6. **写 `note`**：说明该证据的局限（截图无实文件、仅图题可辨、数据表无法复算等）。
7. **收尾统计**：统计证据总条数与 `text/code/figure/table` 分类计数，写入 `steps[1].outputSummary`；
   把"哪一点证据薄弱/无证据"写进 `steps[1].note`，为下游复核埋点。

规模基准（`sample-01` 实测）：**28 条证据 = text 17 + code 7 + table 3 + figure 1**。

---

## 5. 判定规则

1. **一个评分点可有多条证据**：`sample-01` 的 R1 引用了 E1 / E2 / E3 三条；证据数量不设上限，但不得凑数。
2. **证据必须"对得上"评分点**：与 `evidenceRequirement` 无关的段落不得作为该点证据（宁缺毋滥）。
3. **行号必须真实**：摘录片段与其行号必须在原文中一一对应，可用行号回读校验。
4. **`kind` 与 `location` 一致**：`figure` 必须带 `figureNo`，`table` 必须带 `tableNo`；缺失时应降低该条置信度并写 `note`。
5. **不得用"图题"冒充"图中内容"**：项目内样例报告的 `figures/*.png` **未随仓库提供**，
   只能依据图题判读，此时该条置信度上限建议 **0.70**（`sample-01` 的 E17 取 0.60）。
6. **证据空数组是合法的**：契约允许 `ScoreItem.evidence = []`（表示"未找到证据"），
   但此情形必须在 Grader 阶段落到 `notMet` 档，并由本环在 `steps[1].note` 中提前声明。

---

## 6. 置信度口径

对齐 `schema.ts` 的 `CONFIDENCE_THRESHOLD` / `docs/contract.md` 第三节：

| 分级 | 区间 | 证据侧含义 |
|---|---|---|
| HIGH 高 | `[0.80, 1.00]` | 原文逐字可核对，位置精确（有行号/图号） |
| MEDIUM 中 | `[0.60, 0.80)` | 证据存在但不完整或有歧义：图题推断、行号缺失、表述含糊 |
| LOW 低 | `[0.00, 0.60)` | 证据薄弱或仅有间接旁证 |

**两条独立口径，不可混用**：

- **单条证据置信度**（`Evidence.confidence`）：只描述"这条引用本身靠不靠得住"；
- **步骤整体置信度**（`steps[1].confidence`）：描述"本环交付质量"，`sample-01` 取 0.86。

`ReviewStep` **没有** `needsReview` 字段，所以低于 0.80 的情形必须在 `note` 里点名（哪一点、为什么）。

---

## 7. 反幻觉约束（红线，不可违背）

1. **找不到就写找不到**：某评分点在原文中确实无对应内容时，该点**不产出证据**，
   并在 `steps[1].note` 明确写出"**未找到相关证据**（评分点 Rx）"。
   由 Grader 据此判 `notMet`、`score = 0`。**这是本流水线的合规红线，不是失败。**
2. **严禁编造引用原文**：`quote` 字段里的每一个字都必须能在原文中检索到；
   不得改写、不得润色、不得把两段话"合成"成一条引用。
3. **严禁编造位置**：不得虚构行号、图号、表号；不确定时省略该字段而非填一个近似值。
4. **严禁越界推断**：不得把"报告没写"解释为"作者默认满足"。
5. **严禁以"常识"补证据**：外部知识不构成报告证据，只能作为 `note` 里的背景提示，且不得计入判分依据。
6. 一旦发现无法回溯的引用，该条证据**必须删除**，并相应下调 `steps[1].confidence`。

## 8. 自检清单（输出前逐条核对）

- [ ] R1–R12 每一点都处理过，无遗漏（总计 12 点）
- [ ] 每条证据都能按 `location` 回原文定位，`quote` 逐字一致
- [ ] `kind` 与 `location` 自洽（figure→图号、table→表号）
- [ ] `id` 在结果文件内唯一，无重复引用
- [ ] 证据条数与分类计数已写入 `steps[1].outputSummary`
- [ ] 无证据的评分点已在 `steps[1].note` 中声明"未找到相关证据"
- [ ] 无任何编造的引用、行号、图号 —— 有疑即删，宁缺毋滥
