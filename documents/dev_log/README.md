# AutoGrader · 研发对话记录（评委审阅指引）

本目录是 AutoGrader 项目**从立项到当前全部研发对话的完整归档**，
对应《AutoGrader 步骤路径规划书_v1.1》**§3.3 LearnBuddy 对话记录归档**。

> **一句话**：这里能让你从「用户提出什么要求」一路读到「最终落了哪些文件」，
> 中间每一步推理、每一次工具调用都可追；不是事后补写的总结稿，而是从 LearnBuddy
> 会话记录里逐字导出的原始文本。

---

## 一、为什么这份记录值得看

AutoGrader 是一个 **Compile-time AI** 项目——智能体的能力不体现在运行时的网页上，
而体现在「如何把一份实验报告解析、取证、逐点评判、算出总分、生成评语」这条链路的构建过程中。
这条链路是怎么一步步定下来的、哪些方案被否掉、哪些口径被冻结、每次改动动了哪些文件——
**全部留在这份记录里，且有对话 ID 可核。**

因此本目录同时承担两个作用：

1. **交付物三的实证素材**（赛事必交 5 项中的「对话记录」）；
2. **项目可审计性的证据**：任何一条已落盘的结论，都能顺着对话编号找回它的来源。

---

## 二、交付要求与达成情况（§3.3 五要素）

§3.3 要求索引完整登记：**日期 / 目的 / 结论 / 产物 / 对话 ID**。

| 要求项 | 达成情况 |
|---|---|
| 日期 | ✅ 每一轮登记日期；每份转录另附精确到分钟的时间跨度（北京时间） |
| 目的 | ✅ 逐轮登记，取用户当轮的真实诉求 |
| 结论 | ✅ 逐轮登记关键裁决与冻结口径 |
| 产物 | ✅ 逐轮登记落盘文件（或注明「对话内产出（未落盘）」） |
| 对话 ID | ✅ 逐轮登记会话 UUID，可直接定位到原始 JSONL 会话记录 |

五要素之外，本归档额外提供了三级可追溯结构（见第四节）。

## 四、三级可追溯结构

看一份记录时，可以按下面的顺序往下走：

**第一级 · 总览表**（`对话记录索引.md` §一）
> 39 轮 / 9 份会话 / 112 次用户输入 / 812 次助手回复 / 2186 次工具调用的规模统计。

**第二级 · 逐轮索引表**（`对话记录索引.md` §二）
> 每一轮一行，含日期、目的、结论、产物、对话 ID，以及**指向对应转录文件的可点击链接**。

**第三级 · 完整转录**（各 `C-xxx-C-xxx.md`）
> 每份转录开头有该会话的元信息表（会话 ID / 时间跨度 / 规模 / 工具成功率）
> 与该会话承载的各轮索引表，随后是**逐字的完整转录**。

**追踪一条结论的完整路径**：
> 索引里看到某轮的「产物」列 → 点「转录」链接 → 在转录里定位到那个时间点 →
> 读当轮的完整来龙去脉 → 得到「对话 ID」→ 可回原始会话记录核对。

## 五、记录的来源与加工方式（如实说明）

### 来源

直接来自 LearnBuddy 的本机会话记录文件（JSONL 格式），
位于 `%USERPROFILE%/.learnbuddy/projects/<项目目录>/` 下。
**不是**事后回忆补写的，也**不是**由 AI 二次概括的。

### 加工方式（这是唯一一处做了取舍的地方，如实声明）

| 内容 | 处理 | 理由 |
|---|---|---|
| 用户输入 | **逐字保留**，未做任何摘要、改写、润色 | 这是最核心的原始证据 |
| 助手回复正文 | **逐字保留** | 同上 |
| 工具调用 | 压成一行（工具名 + 关键参数 + 成功与否 + 返回字节数） | 让读者看清「这一步干了什么」，而不被参数 JSON 淹没 |
| 工具返回正文 | **剔除** | 属过程噪声（文件内容、命令回显等），保留会使体积膨胀数十倍且无可读性 |
| 内部推理（reasoning） | **剔除** | 属思考过程，非结论；结论已体现在助手回复正文中 |
| 环境快照 / 系统提示注入 | **剔除**（含 `<user_query>` 等标签已解包还原） | 非对话内容 |
| 中断的轮次 | **保留并标注** `Interrupted by user` | 让「为何这段时间无产出」有据可查 |

> **一句话**：凡属「谁说了什么」的，一字未改；凡属「机器跑了什么」的，压成一行；
> 凡属「系统自动注入的」与「模型内部思考的」，已移除。

### 规模

| 项 | 值 |
|---|---|
| 原始会话记录 | 约 33 MB / 7501 行 |
| 本归档 | 11 份文件 / 874 KB（约 1/38） |
| 覆盖对话轮次 | **39 轮（C-000 – C-038）** |
| 覆盖会话 | 9 份 |
| 用户输入 / 助手回复 | 112 次 / 812 次 |
| 工具调用 | 2186 次（成功 2180 · 失败 0 · 无结果回报 6） |
| 时间跨度 | 2026-09-25 11:20 → 2026-09-26（北京时间） |

> 「无结果回报」指调用已发出、但其结果未落入会话记录的情形（均为用户中断会话所致），
> 已在对应转录的头部单列，不计入成功率分母，也未从工具调用总数中隐去。

## 六、与项目其他文档的关系

本归档**不是**孤立的一份材料，它与工作区根的《项目总纲与同步状态.md》**同源**：

- 《项目总纲》§九「对话归档索引」是真源索引，本目录的索引由同一次导出生成，
  **两份不可能对不上**；
- 每条对话的「产物」列指向的文件，都在仓库内实际存在，可逐一点开；
- 若需要理解某一轮的技术背景，可对照仓库内的 `docs/contract.md`（契约口径）、
  `AUDIT.md`（缺陷清单）、`documents/项目总纲与同步状态.md`（当前状态）。

## 八、可复核性声明

本目录中的每一份转录都是**机器导出**的，导出脚本的每次运行都带有完整性断言
（磁盘上每一个会话记录文件都必须被登记，否则中止导出），因此**不存在「挑了好看的几轮放进来」的可能**：

- 覆盖 C-000 至 C-038，**连续无缺号**；
- 包含 2 轮「无结论 / 被中断」的会话（C-000、C-027），未做美化删除；
- 工具调用总数与成功率如实在每份转录头部列出。

**这份记录的价值恰恰在于它没有被修饰过。**
