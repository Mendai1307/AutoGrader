## 四、硬约束与核心口径

1. **LearnBuddy 为唯一指定平台**；不引入 `openai` / `anthropic` / `langchain-*` 等第三方 AI 依赖
2. **Compile-time AI 范式**：AI 推理在 LearnBuddy 对话侧完成 → 产出 `ReviewResult` JSON → 提交进仓库；
   Web 端运行时**零 AI 调用、零后端**
3. **总分口径（写死，不得改写）**：`总分 = Σ (score / maxScore) × weight`
   —— **不是** `Σ (score × weight / 100)`。各评分点 `maxScore` 为教师自定标度，占比只由 `weight` 决定
   权重序列（和 = 100）：**5 / 12 / 5 / 7 / 20 / 10 / 11 / 13 / 7 / 5 / 3 / 2**
4. **耦合枢纽**：Zod 定义的 `ReviewResult` 契约 —— 同时约束智能体输出、前端类型、仓库数据
5. **5 项必交**：作品链接 / 3 分钟 Demo 视频 / 作品介绍 PPT（含团队成员信息）/ 源码仓库 / LearnBuddy 对话记录
6. **对话记录从 2026-09-25 起持续丰富**，按「九、对话归档索引」规范归档

- `tencent-local-office-edit` 技能对本机**大文件 / 中文路径** docx：`open_file` 后调读接口会持续报
  `DocEditor::GetOutline: document is not open`。
  **绕法**：用 Python 直接解析 docx（`zipfile` + `word/document.xml`）**只读**提取段落与表格文本，
  脚本见 `.work/extract.py`（用法：`python extract.py <in.docx> <out.txt>`）。
- 同技能 `create_doc` → `doc_insert_markdown`（`markdown` 支持传 `file://<绝对路径>`，避免超长参数）
  → `save_file` 链路**可用**，用于生成 DOCX 交付物。
- **进程与文件占用自查**（用户 2026-09-25 规定：每轮结束前必须释放产物与工作区内文件的进程）：
  - 可靠做法：`tasklist 2>/dev/null | grep -iE "python|node\.exe"`
  - ⚠️ `tasklist //FI "IMAGENAME eq ..."` 在 Git Bash 下**时灵时不灵**（会报「无效参数」），不要依赖
  - ⚠️ `ps -W` 在本机沙箱**不可用**（返回 0 行），不能作为判据
  - ⚠️ `wmic` 被当前安全策略**禁用**（属系统级工具），无法据此查进程命令行
  - 本机常驻 **4 个 `node.exe`**（各约 47–51 MB），系宿主应用自身驻留，
    **不是 AI 启动的，不得结束**
- **删除类命令有 safe-delete 钩子**：`rmdir` / `Remove-Item` 会被拦截并转投回收站；
  传 MSYS 风格路径（`/e/Mendai/...`）会因「must be absolute」失败。
  空目录改用 PowerShell `Remove-Item -LiteralPath "E:\..." -Confirm:$false` 可成功。
  > ⚠️ **2026-09-26 修正**：末句（PowerShell 可删）**已不成立** —— 该次实测报
  > `[safe-delete][SAFE_DELETE_FAIL_CLOSED] trash-failed: 这个系统不支持该功能`。
  > 关于本机删除能力的完整取证（注入方式 / 两类失败 / 提权效果 / 哪条路可行）见本节末尾的
  > 「⛔ 宿主的 safe-delete 拦截器」条，该条为**唯一现行结论**。
  > 另：**`fs.renameSync`（重命名/移动）始终可用**，是本机唯一可靠的「清理」替代手段。
- **不得在 Bash 里内联调用 PowerShell**：会被安全策略拒绝
  （「Invoking PowerShell from Bash bypasses PowerShell security checks」），须改用 PowerShell 工具。
- **Node 可直接加载 TypeScript，不必安装任何东西**：`node --experimental-strip-types <file.ts>`
  可加载 v0.1 的 `frontend/lib/schema.ts`（zod 3.24.1 已在其 `node_modules` 内）。
  用途：用 v0.1 的 **Zod 契约**校验历史资产，与工具链 T5 形成双端验证，**且完全不修改 v0.1 仓库**。
  会有一条 `MODULE_TYPELESS_PACKAGE_JSON` 警告，无害。
- **Python 与 JS 的舍入不等价（已踩过）**：Python 内置 `round()` 是**银行家舍入**，
  JS `Math.round` 是 **half-up**，在 `.xx5` 边界分叉（`round(2.675, 2)` → `2.67`，JS → `2.68`）。
  契约指纹算法两侧必须统一用 JS 语义的 `round2`（见 `contract/fingerprint.py` 的 `js_round2`）。
