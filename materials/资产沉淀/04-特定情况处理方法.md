# 04 · 特定情况处理方法

> 可直接照做的处置手册。每条格式：**触发条件 → 处置 → 判据**。
> 与 `03-试错经验.md` 的分工：03 讲「为什么会这样」，04 讲「现在该怎么做」。

## 一、删除 / 清理类操作被拦

**触发**：`rm` / `Remove-Item` / 脚本批量删临时目录失败，报批量闸或回收站失败。

**处置**：
1. 先问「这件事能不能**用移动代替删除**」——重命名/移动到过程目录始终可用。
2. 确实必须删除且单轮 ≥ 50 项 → **向用户提权申请**（不要自行调阈值、不要改环境变量让拦截器不注入）。
3. 提权后仍失败 → **如实说明这不是权限问题**，把「试过什么、失败证据、卡在哪一层」摊清转交用户。
4. 给出用户侧一条命令，由用户在**自己的终端**执行。

**判据**：文件系统的真实状态（存在性检查），不是错误文本。

## 二、本机构建产不出静态产物

**触发**：编译与类型检查通过、静态页生成成功，但最后一步失败、拿不到导出目录。

**处置**：
1. 每次尝试前先把中间目录**整体移走**（让构建建全新目录，不与拦截器交互）。
2. 失败后**重跑一次**才能拿回完整产物（失败会污染中间目录）。
3. 保留「编译 ✓ / 类型检查 ✓ / 静态页生成 N/N ✓」作为等价证据。
4. 交付与判据仍以正规构建产物为准，临时预览服务**只用于看界面，不作为交付物**。

## 三、docx 读不了 / 要改 docx

**触发**：编辑器接口报文档未打开；或需要修订 docx 交付物。

**处置**：
- **只读提取**：用 Python `zipfile` + `word/document.xml`，不要依赖编辑器接口。
- **要修订**：走三段链路 —— ① 转 md（复用解析器的结构树，**不要自己写解析**）→ ② 改 md → ③ 转回 docx。
- **验证两步**：① 回读新文件比对「应存在的 / 应清除的 / 应保留的 / 原稿未被动过」；
  ② **逐块比对新旧结构**。

**判据**：块数与标题数不变、差异块数**恰好等于**预期改动处数。

## 四、真实产出被判「不合规」

**触发**：跑通了流程，但契约校验说输出不合法。

**处置**：
1. 先判断是「**取值域太窄**」还是「**值算错了**」——前者修契约（放宽取值域，属 MINOR），后者修数据。
2. 修契约时坚持**向后兼容超集**：新增字段一律 optional，先跑一遍历史资产回归。
3. 契约是真源，**机器可读 schema 与人类可读说明必须同时修订**。

**判据**：历史资产**一行不改**且通过校验的数量 = 全部。

## 五、要给历史数据加字段

**触发**：新契约需要旧数据补字段。

**处置**：
1. **在副本上做，不动原件**（原件是已公布资产）。
2. 由纯推导得出新字段值，不要引入新的人工输入。
3. **必须同时重算指纹**（指纹覆盖整个对象，含新键）。
4. 落盘保持换行风格一致。

**判据**：新副本通过校验，且原件目录零写入。

## 六、要让「网页」与「本地桌面应用」联动

**触发**：希望网页上点一下就把本地应用唤起并预填任务。

**处置**：
1. 协议名**必须以本机实测注册表为准**，不要照抄文档里的默认值。
2. 用**顶层真实超链接 + 用户点击**触发（脚本静默跳转会被丢弃）。
3. 参数必须做 URL 编码；注意长度上限（参数本身有字符上限，命令行另有总长上限）。
4. **必须做降级链**：深链失败 → 剪贴板兜底 → 静态结果页。未安装客户端时不能出现「死按钮」。

**定性提醒**：这是**操作系统级用户主动唤起**，不是 API 调用、不绕过授权、不自动执行；
对外说明时必须如实这样表述。**不做**「网页自动执行并回读结果」的承诺——没有该通道。

## 七、导出 / 归档对话记录

**处置**：
1. 认可的口径：用户与助手的文本**逐字保留**；工具调用压一行；工具返回正文与推理剔除。
2. **必须带完整性断言**：磁盘上每个会话文件都要在登记表内。
3. 计数统一为**渲染行数**口径；未回报结果的调用单列说明。
4. 设计上**不做删除**（用时间戳快照/原地覆盖），因此可安全重跑。

## 八、安装 / 创建专家包

**处置**：
1. 落点必须在 `my-experts` 目录下，**放错目录等于完全不可见**。
2. 走官方三步：初始化 → 校验（有 error 不能注册）→ 注册。
3. 注意硬性约束：标签与快捷提示词**各恰好 3 个**；智能体定义文件的 frontmatter **禁止声明工具字段**。
4. 不要手改市场缓存文件——它由服务端下发、会被刷新覆盖。

**判据**：官方校验脚本 0 error；注册表（市场清单）里能查到该条目。

## 九、跨会话续接一个长项目

**处置**：
1. **先读项目总纲**（跨对话唯一对齐入口），不要从零重建上下文。
2. 扫会话记录目录，把**未索引的会话补录**进总纲索引；索引行与日志编号**同一轮内一起登记**。
3. 记忆分层使用：每轮都要用的写长期记忆，偶发查证的写附录，过程记录写每日日志。
4. **动手前先按修改时间盘一遍目标目录**，确认哪些文件是此前轮次已写过的。

## 十、引用 / 证据要对齐原文

**触发**：逐字引用校验频繁报不匹配。

**处置**：
1. **引文不要手抄** —— 用起止标记从解析结果的**逐字字段**截取，再交给引用校验器比对。
2. 根本原因是中英文引号、全半角差异会造成**假不匹配**。
3. 行号回链用「块首行在源文件里定位」，不要另建一套坐标。

## 十一、评测发现自身短板

**触发**：分组指标显示某一段误差明显偏大（如低分档）。

**处置**：**主动披露，不掩盖**。把短板连同分组视图一起公开，写进交付说明的「已知局限」，
并说明下一步的改进方向。**判据**：公开数字必须能被第三方用同一份数据复算出来。

## 十二、判断「一个能力该不该做成工具」

**处置**：逐条核对三条判据，**全中才做成工具**：
① 同输入必得同输出；② 可被第三方复算；③ 输出里不出现形容词。
任一条不满足 → 留在技能层，由 AI 承担。

**延伸**：平台**不允许自行注册工具**，确定性能力只能做成**可执行脚本**（CLI + JSON 出参），
由内置的 shell 通道调起；纯函数库没有调用通道。

## 十三、静态站点在本地起不来 / 首页能开但白屏

**处置**：这是「构建期被固化的资源前缀」与「实际托管路径」不一致导致的经典故障。
判断顺序：① 产物内资源地址带什么前缀 → ② 托管在什么路径 → ③ 二者是否一致。
本地预览用**能自动识别前缀**的预览服务，不要手工同步配置。
（该问题已沉淀为可复用技能：`nextjs-static-subpath-preview`。）

## 十四、行为纪律（与本项目所有处置配套）

| 纪律 | 内容 |
|---|---|
| **事不过三** | 同一问题最多自行尝试三次；仍不成即停下转交，不再换路径试探 |
| **不绕护栏** | 禁止调高安全阈值、清空注入变量等绕过宿主安全机制的做法 |
| **受阻提权** | 权限类阻塞主动申请审批；审批后仍失败即说明不是权限问题 |
| **只改点名对象** | 点名之外的顺带发现**只提不做**，列成「待确认的改动」清单交用户裁决 |
| **不用推测补需求** | 缺信息就先做能确定的部分，或动手前一次性问清 |
| **每轮释放进程** | 结束前释放产物与文件的占用，否则用户无法修改自己的文件 |
| **写清为什么** | 重要决策记录 Rationale，而不只记录结论 |
