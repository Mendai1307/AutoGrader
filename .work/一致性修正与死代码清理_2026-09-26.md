## 三、端到端实跑查出的一处 P0 级契约冲突（**未改，待你裁决**）

**这是本轮最有价值的发现。** 按设计流程实跑 `T1 → T2 → T3 → T4 → T5`，在最后一步暴露：

```
[T4] exit=0  total=92.0  weightIncluded=100.0  isPartial=False  grade='A'
[T5] grade='A'（T4 原样）  exit=1  exitReason=errors  errors=[('schema.oneOf', '$.total.grade')]
[T5] grade=None（把等级抹掉） exit=0  exitReason=ok     errors=[]
```

- **根因**：`contract/ReviewResult.schema.json` 把 `Total.grade` 定义为
  `oneOf[ $ref ScoreLevel, null ]`，而 `ScoreLevel` 的枚举是 `excellent / meeting / partial / notMet`
  ——那是**逐项的语义档位**（`scores[].level`）的取值域，不是等级。
- **实际生产者**：T4 的 `DEFAULT_BANDS` 产出的等级是 `A / B / C / D / F`（C-025 的 P2-24 ④ 明确裁决
  「档位名与默认档位同序列、跳过 E」），且 `--grade-bands` 允许用户**自定义任意数量的档位名**，
  所以这个值域**本来就不可能用固定枚举表达**。
- **影响**：任何**满权重且已映射等级**的评阅结果都会在 `schema.structure` 这一项失败、T5 退出码 1
  → 按 S5 规则「任一失败即整体失败」，**模式 2 的正常产出会被判为不合规**。交付物二（Web 端）若消费
  这类结果也会受影响。12 份历史 1.0.0 资产不受影响（它们没有 `total` 子对象）。
- **两处旁证**：`docs/contract.md` §5.4 只写了「何时映射」，**未定义取值域**；
  T5 自测里用的是 `{"oneOf":[{"type":"string"},{"type":"null"}]}`（宽松版）——
  这正是自测没能抓到它的原因。
- **建议改法（最小）**：把 `Total.grade` 改为 `{"oneOf":[{"type":"string"},{"type":"null"}]}`
  （即「等级名或 null」），并在 `docs/contract.md` §5.4 补一句取值域说明；
  同时按 §二 的版本规范决定是否升 `1.1.0 → 1.2.0`（改类型属 MINOR；现有资产无一个带 `total`，故无迁移成本）。
- **为什么我没直接改**：它落在**你没点名的对象**（已冻结的契约层）上，且契约的文件头部写着
  「两者必须同时修订，不得只改一处」+ 有版本递增规范——属于「先说明、不擅动」的情形。
  **你说改，我一处改齐（schema + docs/contract.md + 版本号级联）并复跑验收。**

## 十一、生成头像的尝试（02:56）与装配器缺陷修复

**用户指令**：生成头像。

### 11.1 结论：本环境**不可用**图像生成工具

按官方 `references/avatar-spec.md` 的要求，先从 `agents/autograder-expert.md` 提取角色特征、构建 prompt
（背景色调取 `10-ProjectQuality` 规定的 **green-emerald**）。然后按规程逐层尝试：

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | `ToolSearch` 以**精确名** `ImageGen` 查找 | ❌ 无匹配 |
| 2 | 以关键词检索（生成图片 / 文生图 / text to image） | ❌ 只返回 `VideoGen` 与 Ardot 系列，**无图像生成类工具** |
| 3 | 按规程先跑 `find-skills` | ⚠️ 它是「找可安装技能」的入口，本身不提供模型能力，不构成补救 |
| 4 | 用 `DeferExecuteTool` 直呼 `ImageGen`（参数符合规范） | ❌ **`Tool "ImageGen" is not available in the current environment or configuration`** |

→ 按官方头像规范的**「生成失败处理」**条款执行（原文：*在 README.md 中标注需手动补充的头像，附推荐 prompt*）：

「漫画/插画风格、符合角色定位」，属于用替代物掩盖未完成。

### 11.2 修掉打包器的一个**破坏性缺陷**（本轮最重要的一件事）

| 阶段 | 做法 | 后果 |
|---|---|---|
| 最初 | `clean_stale()`：**先整体删目录、再写入** | 重复装配时被宿主 **「单轮删除 >50 项需确认」** 的安全闸打断在半途 → **包被打坏**（README 被删） |

| **最终** | `stale_items()`：**只报告、不删除**；要删须显式 `--prune` | 装配器**不再具备破坏性**。自测改为 5 条：残留被报出 / 清单内文件不被报 / **任何情况下都不删任何文件** / `avatars/` 与会话标记不算残留 |

### 11.4 两条读数事实（附一处**我先前的错误判断，已改正**）

**旁证**：参考包 `frontend-design-expert/`（由官方链路创建）**同样没有这个文件**。
