# S4 · 总分计算

| 项 | 内容 |
|---|---|
| Skill ID | S4 |
| 所属任务链 | 流程 B · 环 3 |
| 对内 Agent | Grader（计算段） |
| 对外名称 | Score Calculator |
| 依赖 Tool | **T4 确定性计算器**（总分 / `W_r` / 上界 / 等级）——原写「契约校验器」有误：契约校验是 T5，且 T5 也只是复用 T4 |

## 目标

按冻结口径算出总分与等级，结果可被第三方独立复算。

## 输入

- S3 的逐评分点建议分与置信度
- Rubric 的 maxScore 与 weight
- 教师终判分（若教师参与了复核）

## 输出

- 总分（**部分分，下界**）
- 等级
- 计算明细：每一项的 `score / maxScore / weight` 代入值
- 待复核项清单 + **未计入权重合计 `W_r`**

## 执行规则

1. 口径写死：`总分 = Σ (score / maxScore) × weight`，
   **不是** `Σ (score × weight / 100)`。
2. 权重序列不得改写：`5 / 12 / 5 / 7 / 20 / 10 / 11 / 13 / 7 / 5 / 3 / 2`，和 = 100。
   maxScore 由教师自定，不影响占比。
3. **待复核项不计入总分求和**。总分因此是**部分分（下界）**，
   取值范围 `[0, 100 − W_r]`，**不做归一化**。
4. 输出必须携带 `W_r`（未计入权重合计），使总分可被解读为
   「暂定 X，上限 100 − W_r」。
5. 求和范围一旦变化（教师确认了新的一项），必须**重算**，不得沿用缓存。
6. 计算明细必须完整留存，保证任何第三方都能逐步复算得到同一个数。
7. 本 Skill **纯计算，不做任何语义判断**。

## 常见失败场景

- 用错口径：写成 `Σ (score × weight / 100)`。
- 把「待复核」项也计入了求和，使总分虚高且无法解释。
- 对总分做归一化：会导致教师每确认一项，总分被重新缩放，
  出现「认真复核反而掉分」的界面表现。
- 教师改了某一项之后没有重算。
- 浮点误差累积，导致与第三方复算结果不一致。
- 只输出总分，不输出 `W_r` 与计算明细，导致总分不可解释。
