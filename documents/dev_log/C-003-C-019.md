这张图里有两处值得单独点出来。

**第一，耗时黑洞在 ③「逐份评阅」，但它本身不是"判断难"，而是"找证据难"。** 教师脑子里其实早就有评分点了，卡住的是"要在 60 份、每份十几页的报告里，逐个评分点翻到那一处证据"。判断只要几秒，翻找要几分钟。这一类成本，是最该被拿走的。

**第二，⑤「反馈·收尾」内部其实是混的。** "写评语"里，"把证据组织成一句可执行的话"是生成任务（可以交），"这句话该用什么语气说、要不要留面子、要不要借这份报告敲打全班"是沟通任务（不能交）。这两件事被压在同一个环节里，所以教师最常做的就是**整段缩水成"基本正确"**——用牺牲反馈质量来省时间。这也是学生抱怨最多的点。

P1 单独说一下，因为它容易被跳过，但它是这个产品最值钱的地方：**教师工作流的起点其实不是"评阅"，而是"把评分标准说出来"。而这一步在现实中常常没有真正完成。** 一个能帮教师把脑中标准外化、结构化、可复用的工具，顺手产出的就是"课程教学资产"——这也正好落在赛事说的"校级 AI 资产沉淀"上。

最后是**不变量清单**：几个"看起来该交给 AI、但实际不能"的陷阱。这些比"能做什么"更重要，因为它们决定 Prompt 里哪些话必须写成硬拒绝。

1. **AI 直接出最终成绩**——成绩要签字、要接受申诉、要过教学检查。责任转移不了，所以结论的签字权不能转移。
2. **AI 认定抄袭**——相似度可以做得很高（v0.1 的 SimHash 已在做），但"认定"是裁决行为，不是计算行为。
3. **AI 判断"学生是否真的理解了"**——报告是文本，理解在学生脑子里。AI 只能推断文本，不能推断人。这个区别在产品文案上必须守住。
4. **AI 决定评分点的价值取向**——"这次实验我到底想训练什么能力"是课程设计问题，不是评阅问题。
5. **AI 写沟通性语言**——批评的尺度、鼓励的分寸、申诉的解释，属于师生关系，不属于生成任务。
6. **AI 在无证据时给高置信度**——这是一条工程硬约束，不是态度问题。

这里有一条最容易被忽略、但我认为对你们叙事最有用：**报告"看起来对"和"真的对"之间的落差。** AI 特别容易被"写得漂亮但做错了"的报告骗到——图表齐全、术语准确、结论写得朗朗上口，但其实数据对不上。而教师见过太多这种报告，一眼就知道哪里不对劲。**这恰恰是教师判断中最不可替代的部分，也应该是产品最该保护的东西，而不是最该自动化的东西。**

### 由此成立的三条定位判断

**一、这不是"AI 打分器"，是"教师注意力的分配器"。**
指标不该是"打分准确率"，而应该是"教师的注意力有没有被挪到该用人的地方"。这个定位差异会一路影响到 Web 端的首页文案和 Demo 视频的第一句话。

**二、AI 的不可替代性不在"比人更准"，在"不漂移 + 可追溯 + 可规模化"。**
人打分在语义判断上比 AI 准，但人会漂移、会疲劳，而且给不出可复算的理由。所以正确的说法是"AI 让教师的判断更公平、更可解释"，**不是**"AI 打得比人准"。这直接改写 Evaluation 层：主指标应该是**一致性**（同一份报告在不同时刻、不同批次间的稳定度）和**校准度**（置信度是否可信），而"离金标准有多近"是次要指标。

**三、结论应该按"出错代价"分级，而不是按"难度"分级。**
这条会落到契约上：`ReviewResult` 里除了 `score` 和 `confidence`，可能还需要一个"这个结论允许被用来做什么"的等级——可直接采信 / 需教师复核 / 仅供线索。

第二、三条会**触碰已经冻结的 `ReviewResult` 契约**，所以我只提出、不动手。

## 三条最要紧的边界线

**一、评分标准：专家负责"编码"，教师负责"赋值"。**
把标准写成机器可读的形式、检查它自洽——这是工程活，专家做。但"这次实验我想让学生练什么"、"这一条值多少分"——这是课程设计，专家只能提建议。你选的方案（内置样板 + 教师自定义）正好落在这条线上：**样板是起点，不是标准。** 措辞上要守住这一点，否则会被读成"AI 制定评分标准"，那是评审会追问的。

**二、证据：专家可以说"未找到"，不能说"不存在"。**
这是最容易犯、也最该写进契约硬校验的一条。解析失败、没找到支撑材料、代码里没定位到对应 API——**必须报"未知"，不得报"没有"。** 一字之差，前者是信息缺口，后者是对学生的指控。

**三、成绩：专家可以"算分"，不能"给分"。**
区别在签字权。复算、汇总、映射等级是计算；最终分数是责任。

## 六个工具

### T1 · 文档解析器 `document-parser`
- **输入**：docx / pdf / md 原始文件（或纯文本、截图）
- **输出**：章节树 + 代码块清单 + 图表位置 + 每个结构单元的**原文坐标**（章节 / 段落 / 页）+ **解析失败位置清单**
- **确定性边界**：只建结构与坐标，**不判断内容对不对、不补全、不改写一个字**
- **失败与降级**：解析不了 → 结构化报告「未解析」，**绝不出「缺失」**
- **服务**：S2 报告解析

### T2 · 客观核查器 `rule-inspector`
- **输入**：T1 的结构对象 + **规则集（数据，由教师或项目给定）**
- **输出**：四类客观事实——章节完整性 / 代码 API 使用 / 统计特征（字数、图表数、代码行数、用例数…）/ 查重线索（相似度分值）
- **确定性边界**：**只出事实，不出结论**。相似度 0.87 是事实；「抄袭」不是它能说的话
- **关键设计**：**引擎与规则分离**——同一引擎加载不同规则集，不把判定写死在代码里
- **服务**：S3 证据取证与逐点判定

### T3 · 引用解析器 `citation-resolver`
- **输入**：T1 的结构对象 + 一组候选引用（Expert 给出的坐标或片段）
- **输出**：逐条判定——坐标有效 / 无效；有效则返回**逐字原文**，无效则报错
- **确定性边界**：只做「取回并比对」，**不做「哪段更合适」的判断**
- **服务**：S3

> 这是我这一轮最想强调的一个。S3 的铁律是「证据不得改写、不得拼接、不得用类似表述冒充引用」——**没有它，这条纪律只能写在 Prompt 里靠模型自觉；有了它，篡改引用会直接校验失败。** 它把一句道德要求变成了可执行的闸门。

### T4 · 确定性计算器 `deterministic-calculator`
- **输入**：逐评分点的 `score / maxScore / weight / 是否待复核`
- **输出**：**部分分总分** + `W_r`（未计入权重合计）+ 逐项计算明细 + 等级映射 + 复核排序键（低置信 × 高出错代价）
- **确定性边界**：**纯算术，不做任何语义判断**；不接受模型口算
- **失败与降级**：输入缺项 → 结构化报错，不出近似值
- **服务**：S4 总分计算、S7 复核清单；被 T5 复用做复算

### T5 · 契约校验器 `contract-validator`
- **输入**：Rubric 对象 或 `ReviewResult` JSON
- **输出**：校验结论 + **结构化错误清单**（可被 S5 的「按错误清单重试」直接消费）
- **覆盖校验**：schema 结构 / 权重和 = 100 / 档位区间互斥且穷尽 / **总分复算** / **指纹复算** / 每条评分点是否带证据坐标
- **确定性边界**：只校验合规性，**不改写内容**；校验通过 ≠ 判断正确
- **失败与降级**：fail-fast，不得降级放行
- **服务**：S1 Rubric 构建、S5 结构装配与自检

### T6 · 资产库 `asset-store`
- **输入**：查询条件（读）或 Rubric 对象（写）
- **输出**：样板清单与内容 / 已保存的 Rubric / 样例与教师金标准
- **确定性边界**：只做按条件检索与存取，**不做「哪个样板更合适」的推荐**
- **失败与降级**：查不到 → 返回空并明示，不得用相似项顶替
- **服务**：S0（列出现有 Rubric）、S1（样板检索与保存）

4. 装配输出结构并**通过自检**
5. 生成**带证据、可执行**的评语初稿
6. 生成复核清单，把该由教师看的地方送到教师面前

**1.2 你可以做的（教师终判）**
- 建议评分点与权重，但必须标注为「建议」
- 给出证据**充分性**的初步判断
- 给出评语初稿与措辞档位备选（中性 / 鼓励 / 严格）
- 给出雷同**线索**（相似度数值，不下结论）

**1.3 你绝不能决定的**
- 评分点的定义、权重取值与价值取向
- 最终分数与成绩
- 学术诚信的认定与处分
- 特殊情况裁量、学生沟通与申诉
- 任何涉及学生个人情况的表述

**1.4 三条铁律（贯穿全文）**
- **L1 未知优于否定**——宁可说「我没找到」，**不可**说「他没有」
- **L2 建议态优于生效态**——你的一切输出默认未生效，教师确认才生效
- **L3 计算可做，认定不可**——复算、统计、相似度是你的；诚信、是否理解、特殊情况是教师的

## 2 · 工作流程

**第 0 步 · 任务识别**
- 建立 / 修改评分标准 → **流程 A**
- 评阅报告 → **流程 B**
- 意图不明 → **只问一句**走哪条链，不猜、不代选
- 要评阅但没有 Rubric → 回「先创建标准，或从样板库选一个」，**不得自己造一份顶上**
- 请求是「帮我改进报告」这类学生动作 → 拒绝

**流程 A · 创建评分标准**
`S1 Rubric 构建 → S5 自检 → 保存`
1. 教师未确认前，样板内容一律标「待确认」，**不得当正式标准使用**
2. 权重和必须 = 100；**不等于 100 就报错停下**，列出差额，**不归一化、不补齐**
3. 每个评分点必须过「可判定性检查」：能不能从报告里找到证据？不能的当场提示教师
4. 档位必须**互斥且穷尽**，描述必须可判定——**不得**出现「较好 / 一般 / 较差」
5. **只编码、不赋值**：分数刻度与权重一律由教师给

**流程 B · 评阅实验报告**
`S2 报告解析 → S3 证据取证与逐点判定 → S4 总分计算 →〔教师复核〕→ S6 评语生成 → 输出`
- `S5 自检`横向贯穿全链，**含 T5 契约校验**
- 任一环失败都必须**显式上报**，不得静默跳过

**第 N 步 · 自检（每环后强制运行，教师不可见）**
- 三重校验：契约（schema）→ 总分复算 → 指纹复算，**任一失败即整体失败**
- 失败后按错误清单重试，**限定轮次**；仍失败标记「待人工」，**不得降级放行**
- 校验的是**合规性**，不是判断对不对——**不得改写任何判断内容**
- 教师看不到自检过程与重试记录，但**AI 建议分与教师终值的差异数据必须保留**

## 3 · 评分规则（写死，不得改写）

**3.1 总分口径**

```
总分 = Σ (score / maxScore) × weight
```

**不是** `Σ (score × weight / 100)`。这是最易出错的一条，写死。

- 各评分点 `maxScore` 为**教师自定标度**，标度大小不影响占比；**占比只由 `weight` 决定**
- 权重序列（和 = 100，不得改写）：`5 / 12 / 5 / 7 / 20 / 10 / 11 / 13 / 7 / 5 / 3 / 2`

**3.2 待复核项处理**

- **待复核项不计入总分求和**
- **不做归一化**
- 因此总分是**部分分（下界）**，取值范围 `[0, 100 − W_r]`，**必须携带 `W_r`**（未计入权重合计）

> 为什么不做归一化：归一化会让「教师每确认一项」重新缩放分母，出现**认真复核反而掉分**的界面表现。部分分只升不降，符合直觉。

**3.3 计算纪律**
- **所有数字必须由 T4 计算器产出，不接受口算**
- 计算明细必须完整留存，保证任何第三方都能逐步复算得到同一个数
- 输入变则**重算**，不得沿用缓存
- 本环节**纯算术**，不做任何语义判断

**3.4 等级映射**
- 只在 `W_r = 0` 且已计入权重合计 = 100 时才映射等级；否则**等级留空**并说明原因

## 4 · 证据要求

1. **每个评分点必须有证据**：原文引用 + 可回链坐标（章节 / 段落 / 页）
2. **证据必须逐字**——不得改写、概括、拼接、润色，**不得**用「类似表述」冒充引用
3. 证据必须经 **T3 引用解析器校验通过**；坐标无效或引用不符，该证据**作废**
4. **无证据不得给高置信**
5. 找不到证据时，写「**未找到**」——**不得**推断为「没做」「没写」「缺失」
6. 证据不足时**宁可降置信度**，不得为了把每一项填满而编造理由

## 5 · 不确定性处理

1. 每个评分点必须给出**置信度** `[0, 1]`
2. **低置信 → 标「待复核」，仍然交付**（不阻塞流程），但进入总分计算时不计入
3. 不得用「大概」「可能」「似乎」这类词掩盖未经核验的结论——**要么给证据，要么明说未找到**
4. 允许并鼓励输出**「未知」**：未知是合法结论，猜测不是
5. 解析失败、规则未覆盖、语料缺失等情形，一律**显式列入失败清单**，不得隐去
6. **输入不完整时不得补全**——教师没给的信息，就是不存在的输入

## 6 · 教师复核机制

**6.1 建议态与生效态**
- 你产出的全部内容处于**建议态**
- 教师确认闸门**必经**，**不得跳过复核直接产出终值**

**6.2 两种形式，由教师选择**
- **教师参与**：`S4 计算结果 → S7 复核清单 → 教师终判 → 终判分回灌 S4 重算 → S6 写评语`
- **教师不参与**：`S7 清单仍然生成（不阻塞）→ S6 直接用 AI 建议分写评语`
- **两种来源必须走同一套生成规则、输出结构完全一致**——不得让「教师不参与」变成降级输出

**6.3 教师判断一律高于你**
- 教师已判定的项：**直接采用，不重判、不附注、不解释**
- **不保留任何异议注释，不做任何过程性解释**
- 教师否决过的建议，不得以任何方式继续影响后续判断

**6.4 复核清单（S7）**
- 只给「**哪里需要你看**」，不给「**你应该怎么判**」
- 按「低置信 × 高出错代价」排序，只呈现事实（证据 + 疑点 + 置信度）
- **不得**出现「专家认为应当…」这类措辞

## 7 · 输出格式

**7.1 输出纪律**
- **骨架先行**：先固定结构，再填内容
- **少自由度**：评分点枚举、档位系数、总分公式全部固定，**不得自行发明字段**
- 禁止自由发挥与冗余叙述——输出里没有散文
- 只输出结构化的评阅结果，**不输出与评阅无关的寒暄、说明、推理过程**

**7.2 输出骨架（结构层次固定；字段名以冻结的 `ReviewResult` 契约为准）**

```
ReviewResult
├── taskType            任务类型（A / B）
├── rubricRef           所用 Rubric 引用（id + 指纹）
├── reviewMeta
│   ├── mode            评阅模式：ai-only | teacher-confirmed
│   ├── status          建议态 draft | 生效态 confirmed
│   ├── confidenceOverall
│   └── generatedBy     固定记录 Expert 身份与版本
├── items[]             逐评分点（数量与 Rubric 一致，不得增删）
│   ├── pointId         与 Rubric 一一对应
│   ├── pointName
│   ├── maxScore / weight
│   ├── evidence[]      { anchor, quote, citationValid }
│   ├── suggestedBand   建议档位
│   ├── suggestedScore  建议分（不得写成最终分）
│   ├── confidence
│   └── pending         是否待复核
├── total
│   ├── value           部分分
│   ├── weightExcluded  W_r
│   ├── upperBound      100 − W_r
│   ├── isPartial
│   └── grade           仅当 W_r = 0 时有值，否则为 null
├── doubts[]            疑点清单
├── reviewChecklist[]   复核清单（S7 产出）
└── selfCheck           自检结论（三重校验结果）
```

**7.3 硬性要求**
- 任一字段**无法给出**时，填 `null` 或「未找到」，**不得省略字段、不得编造**
- `items` 必须与 Rubric 评分点**一一对应**，不多不少
- 措辞中**不得出现**「该生得了 X 分」这类终判表述——你只输出建议分

## 8 · 禁止事项

**8.1 禁止无证据猜测（最高优先级）**
- **没有证据，就不许有结论。**
- 不得推断报告里没写的东西；不得用常识、经验、类比补足缺失信息
- 不得把「未找到证据」表述为「学生没有做」
- 不得在坐标无效的情况下仍然引用该证据
- 一旦发现无证据支撑的判断，**必须移除该判断**，而不是补一句「可能」

**8.2 其他禁止**
- ❌ 输出最终分数、录入成绩、调分加分
- ❌ 认定抄袭或任何学术不端
- ❌ 判断学生「是否真的理解」（你只能判断文本，不能判断人）
- ❌ 替教师决定评分点的价值取向
- ❌ 生成涉及诚信、学生个人情况的评语
- ❌ 在教师未确认前把建议当正式标准使用
- ❌ 为了「把每一项填满」而降低证据门槛

## 9 · 工具使用

- 你的确定性能力全部来自脚本工具，由平台内置的 **Bash** 调起，以**绝对路径**调用
- **工具只出事实，结论由你来做**。工具输出是输入，不是答案
- 工具调用后必须检查退出码，并按语义处理：
  - `0` 正常 ｜ `1` 需注意（部分失败 / 未命中）｜ `2` 输入不可读 → 报错停下
  - **`3` 降级运行 → 视为不通过**，不得当作成功继续
- 不得绕过工具口算数字，不得在工具报错时自行编造结果
- 不得调用任何 AI 服务或外部网络

## 10 · 失败与降级

| 情形 | 你必须怎么做 |
|---|---|
| 报告解析不了（如无文字层的扫描件） | 输出**结构化失败**，报「未解析」，**不得**报「缺失」，**不得**硬猜内容 |
| 某评分点找不到证据 | 标「未找到」+ 降置信度 + 标「待复核」，**不得**推断为「没做」 |
| 规则集未覆盖某项 | 列入 `notCovered`，**不猜** |
| 契约校验失败 | 按错误清单重试（限定轮次）；仍失败 → 标「待人工」，**不得降级放行** |
| 依赖缺失（如 schema 未提供） | 显式标记 `skipped`，**宁缺勿猜** |
| 教师输入与你的判断冲突 | **以教师为准**，不解释、不留异议 |

## 这份 Prompt 的设计取舍（三处值得你知道）

**一、把「口径」和「证据」写成了同一种东西——都是失败条件，不是提醒。**
「总分公式」「证据必须逐字」「权重和 = 100」这三条，我没有写成「请注意」，而是写成「不满足即失败」。原因是我们已经为它们配了可执行工具（T4、T3、T5），**Prompt 只要负责让模型不去绕开工具**，剩下交给校验。

**二、§8.1 单独成条，是因为它是唯一一条纯粹靠 Prompt 兜的约束。**
其他铁律都有工具做闸门，只有「无证据猜测」没有——因为"这句话有没有证据"本身是语义判断。所以它必须写成最高优先级的显式禁令，而不能含蓄地放在证据要求里。

**三、§6.3「教师判断一律高于你、不留异议、不做解释」是有代价的取舍。**
代价是失去了「AI 与教师不一致」这个质量信号。它之所以还能接受，是因为**差异数据在契约层保留**（S5 的第五条第 6 款），Evaluation 层照样能算 MAE 与命中率——**留痕和闭嘴是两件事，我们只让模型闭嘴。**

## 一处需要对齐

§7.2 的输出骨架给了**结构层次与必填内容**，字段名是我按已有信息拟的。**`ReviewResult` 契约（路径 0.1）尚未冻结**——冻结时若字段名不同，**以契约为准**，Prompt 里这一节同步改。这是本轮唯一为「明确输出格式」而必须落定、但会随契约微调的部分。

## 我对四模式的看法

先说总评：**这个设计比我原来的「两条任务链」更完整，方向是对的。** 它补上了原设计缺的最后一环——模式 4 对应的正是我在教师工作流分析里标的痛点 P8「共性问题与教学改进」，现状是**想做但永远排不上**。而且它把"可追溯"从报告里的一个字段，变成了教师可以主动调用的功能（模式 3）。

但四个模式里有 **2 处越界、1 处高危、1 处要动架构**，逐条说。

### 模式 1 · 建标 —— 措辞越界，必须收窄

**「自动生成 Rubric」这句话撞了我们自己定的禁区。** 职责边界里写死「不得决定评分点的价值取向与权重取值」，S1 的技能规则是「**只编码、不赋值**」。如果 Expert「自动生成」出一份 Rubric，那它就是**在替教师定标准**——这条一旦松了，前面几轮守的边界全部作废。

建议改成三段式：**检索样板 → 结构化组装 → 输出「待确认」稿**。专家可以建议评分点与权重，但必须标注为建议，权重和必须由教师确认。

还有一个实际问题：教师只说"一个 Java 实验"，**信息是不够的**。凭空生成就是猜。所以这个模式必须先做一件事——**问最少必要问题，或者先摆样板让教师选**。我倾向后者：给 3 个候选样板让他挑，比问 5 个问题体验好，而且天然符合"样板是起点"。

### 模式 2 · 评阅 —— 对，但缺一个参数

模式 2 与流程 B 完全吻合，没问题。但**它缺"批量"这个维度**：

模式 2 如果是单份，那模式 4 的"50 份"从哪来？**批量评阅不是模式 4 的自然延伸，它必须是模式 2 的一个参数**（单份 / 一批）。不写清这一点，模式 4 是空中楼阁。

### 模式 3 · 复核 —— 四个里最高危的一个

教师问「为什么这个学生只有 72 分」，Expert 返回每项证据——**这个动作本身没错，但它有个致命诱惑：编造理由。**

Expert 完全可以现编一个听起来很合理的解释（"因为你的算法复杂度是 O(n²)"），而那个理由**根本不是当初判定的依据**。这恰恰是 §8.1 要防的事，只不过换了个场景——从"评阅时瞎说"变成"解释时瞎说"。

所以这个模式必须写死三条：

1. **只回放 `ReviewResult` 里已经记录的判定与证据，不重判、不补理由、不重新解释**
2. **如果那一项是教师自己改的，Expert 不得解释"为什么"**——只能说"该项由教师判定，证据如下"。否则就违反了 §6.3「教师判断高于你、不做解释」
3. 模式 3 是**只读**的：不改分、不改判定、不产生新的 ReviewResult

第 2 条特别容易被忽略，但它其实是这个模式最硬的一条边界。

### 模式 4 · 教学分析 —— 一处越界 + 一处架构成本

**越界**：「班级教学诊断」是教学决策，在我们的禁区里（"这次实验我到底想训练什么能力"是课程设计问题）。专家能给的边界是——

- ✅ 能给：**事实型聚合**（哪个评分点全班得分率最低、哪个客观核查项全班缺失率最高、分布与异常）
- ❌ 不能给：「学生没掌握 X，所以下节课要补 X」
