## 结论：能，而且不用动架构——但今天现场复核发现一条会让按钮"点了没反应"的硬约束

`learnbuddy://task?action=start&prompt=<URL编码>` 这条路**在本机当前状态下成立**；但**把 SYSTEM_PROMPT 全文内联进去会超长失败**，必须改成"极简指令 + 智能体自取全文"。

### 一、现场复核（今天实测，非沿用 9-22 结论）

1. **协议注册仍有效**：`HKCU\Software\Classes\learnbuddy` → 默认值 `URL:learnbuddy`；`shell\open\command` → `"H:\LearnBuddy\LearnBuddy.exe" "%1"`。注册表里名字含 `buddy` 的项**只有 learnbuddy**，`workbuddy` 未注册 —— 网上 `workbuddy://` 的写法在本机必然失败。
 *取证方式*：`reg.exe` 与 PowerShell 读注册表在本机被安全策略拦截，改用 Python `winreg` 只读读取，脚本 `.work/regcheck.py`（已附）。

2. **深链契约在当前客户端里逐条命中**——从 `app.asar` 直接提取到 `parseDeeplink` 源码：
 ```
 action 必须是 "start"，否则 invalid-action
 prompt 解码后超 8000 字符 → 静默截断（提示「长内容应走 payloadId」）
 payloadId / prompt / promptContentBlocks 至少一个，否则 missing-required
 可选：expertId / skills / connectorIds / model / mode / welcomeMode / permissionMode
 VALID_WELCOME_MODES = coding | working | design
 VALID_PERMISSION_MODES = default | fullAccess（本项目只用 default）
 ```
 → 9-22 那份评估的结论**没有过期**。

3. **行为定性仍是「草稿预填，不自动执行」**：包内存在 `deeplink.task.draftOverwrite.title = "覆盖当前草稿？"` 等确认文案，全包无 autoSend。**用户仍需自己点发送**。

### 二、两条硬约束（9-22 评估未覆盖，今天新发现）

**① 体积超限——这条会让按钮"点了没反应"**

`agents/agent/SYSTEM_PROMPT.md` 6,088 字符（其中中文 3,369）。解码后 6,088 < 客户端 8,000 上限 ✅，但：
- `encodeURIComponent` 后 = **37,703 字符**
- 拼成完整深链 = **37,784 字符**
- Windows 命令行参数上限 = **32,767** → **超限约 15%**

解法（推荐前者）：
- **极简指令 + 自取全文**：深链只放 ~150 字（"你是 AutoGrader 实验报告评阅专家，请先读取 `<仓库 raw 地址>` 中的系统指令并严格执行"）→ 编码后 ~500 字符，深链总长 ~600。智能体有内置 WebFetch，能自己把全文读回来；**仓库仍是唯一真源，改 Prompt 不用重新部署网页**。
- 或裁一版 ≤1,500 字的紧凑内联 Prompt（编码后 ~9,000 字符，仍在安全区）。

**② `expertId` 用不了**

`expertId` 是召唤平台上**已注册**专家的参数；我们的交付物一是 `backend/autograder-expert/agents/` 下自定目录结构的**暂存稿**，平台侧尚未注册 → 深链必须**自带角色定义**。`skills=` 同理（S0–S7 未发布到生态，拉不起来）。

**附带**：`cwd` 在网页端被忽略（i18n 原文「Web 端不支持本地路径，已忽略 deeplink 中的目标目录」）→ 从 GitHub Pages 拉起**无法指定工作目录**，报告文件仍要用户手动拖入。

### 三、网页侧（沿用 9-22 结论，本次未推翻）

而且有一个**不可控硬前提**：那台机器必须已安装对应品牌的 LearnBuddy 桌面端。装不了就没得谈——网页无法探测、也无法代为安装。

### 一、那台机器上"装专家"的四条通道（本次实测）

专家包固定落点 `$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/<专家名>/`，并在同级 `.codebuddy-plugin/marketplace.json` 登记；**不在该目录下就"无法被检测到"**。本机实为 `~/.learnbuddy/plugins/...`（LearnBuddy 品牌包把配置目录指向 `.learnbuddy`）。

| 通道 | 实测机制 | 可用性 |
|---|---|---|
| **内置 `expert-manager` 技能** | 随客户端分发（`resources/builtin-skills/expert-manager/`），脚本链 `init_expert.py → validate_expert.py → register_expert.py` | ✅ **唯一能由智能体自主驱动**的通道 |
| 深链 `skills=` | `resolveDeeplinkSkills` → 已装直接用；未装则 `installFromEcosystem` → `marketplace.builtin.list/install` | ⚠️ 走的是**平台自有技能市场**（需账号/企业 ID），**不支持任意 GitHub 仓库** |
| 插件市场「添加市场」 | 云侧 `POST /console/as/marketplace/sources`，`source_type = url \| github` | ⚠️ 需账号与后端；桌面侧走 daemon `plugin.addPluginMarketplace`，接受何种来源**未取证**（daemon 是独立二进制） |
| 深链 `expertId` | `expertAPI.summon(id, source:"task-deeplink")` | ❌ **首次用不了**——那台机器上专家还不存在；装好后再点才生效 |

最要紧的推论：既然只有内置技能能自主驱动，"从 GitHub 拉包并安装"实质等于**让评委机器上的智能体把我们的专家包重走一遍 `init → 写文件 → validate → register`**。可行，但会引入内容重生成的输出漂移。

### 二、更稳的做法：仓库里放**已合规**的专家包，prompt 只做"复制 + 注册"

但包里必须过校验。以下是从 `validate_expert.py` 实提取的**硬错误**规则：
- 必须有 `.codebuddy-plugin/plugin.json`，含 `name`（kebab-case）+ `version` + `description`
- `expertType ∈ {agent, team}`；`agents/<agentName>.md` 必须存在
- `displayName` / `profession` / `displayDescription` / `defaultInitPrompt` 四字段各须含 `en` + `zh`
- `tags` **恰好 3 个**、`quickPrompts` **恰好 3 个**；`categoryId` 取自 12 个固定分类
- **`skills[]` 每项必须是含 `SKILL.md` 的目录**
- 根下禁止 `hooks/` `commands/` `.lsp.json`；`agents|skills|bin|avatars` 不得放进 `.codebuddy-plugin/`
（头像缺失、README 缺失仅告警，不阻断）

**现有交付物一的差距——整体不合规，是这条链路的第一个真实阻塞项**：
`backend/autograder-expert/agents/` 现为 `agent/SYSTEM_PROMPT.md` + `skills/S0–S7`（扁平 `.md`）+ `tools/T1–T6` + 空目录 `workflow/`、`evaluations/`，需要：
- Prompt → `agents/<agentName>.md`（不是 `agents/agent/SYSTEM_PROMPT.md`）
- 8 个 Skill 目录化为 `skills/<name>/SKILL.md` × 8，否则 `skills[]` 校验直接失败
- `tools/` → `bin/` 或 `skills/<name>/scripts/`
- `workflow/`、`evaluations/` 不是插件根识别目录 → 改为 `skills/<name>/references/` 或并入 agent 正文
- 补 `.codebuddy-plugin/plugin.json`、`avatars/`、`README.md`

### 三、"一键"实际是几键：三条边界
1. **深链只预填、不执行** → 评委必须自己点发送（1 次）
2. **`permissionMode=default`**（本项目明确不用 `fullAccess`）→ 写文件、跑命令逐项确认（约 2–3 次）
3. **安装有安全闸**：设置项「自动安装非高风险技能」**默认关闭**；高风险内容另有倒计时确认框

### 四、两个真正会砸场的前提
- **那台机器没装桌面端** → 点下去**毫无反应**，网页测不到也补不了
