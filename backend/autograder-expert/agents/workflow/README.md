# Workflow 层 · 索引

> 本目录是「AutoGrader Expert」专家智能体包的 **Workflow 层**（五件套之四）：
> 把 Prompt / Skills / Tools 三层**组织成一条可跑、可回退、可留痕的认知流水线**。
>
> 本层是**规格层**，不产出代码：编排由 Expert 在 LearnBuddy 对话中执行，
> 其中的确定性动作（解析 / 核查 / 引用校验 / 计算 / 契约校验）一律交给 Tools 层脚本，由平台内置 `Bash` 调起。

同级目录（`../`）：`agent/`（Prompt）、`skills/`（方法论）、`tools/`（确定性工具）、`evaluations/`（评测）。

## 二、流水线一览

```
                 ┌──────────── 模式 2 · 评阅 ────────────┐
报告 ──▶ ① Parser ──▶ ② Evidence ──▶ ③ Grader ──▶ ④ Reviewer ──▶ ⑤ Feedback ──▶ ReviewResult
            S2           S3(取证)      S3(判定)+S4      S5              S6
            T1           T2 + T3       T3 + T4          T5              —
                 └──────────────────────────────────────┘
                            ▲
                    S7 入口 A（复核清单）插入在 ③ 之后、⑤ 之前，服务于**教师复核节点**（人，不是环）
```

| 环节 | 一句话 |
|---|---|
| ① Parser | 把报告变成**带坐标的结构**——后续所有引用的坐标源 |
| ② Evidence | 逐评分点**取证**，并把引用送 T3 校验——**证据忠实度的唯一硬闸门** |
| ③ Grader | 逐项判定 + 纯算术算总分——**所有数字由 T4 产出** |
| ④ Reviewer | 装配成合规 `ReviewResult` 并**六项自检**——失败即整体失败 |
| ⑤ Feedback | 逐句挂证据生成评语——**不产生新事实，只产生表达** |

## 三、与三种模式的关系（本层只覆盖「评阅」的那一条）

| 模式 | 是否走五环 | 实际链路 |
|---|---|---|
| **1 建标** | ❌ 不走 | `T6 给候选样板 → 教师选 → S1 构建 → S5 自检 → 保存`（两步能力 + 自检，无逐点取证与判分） |
| **2 评阅** | ✅ **就是这五环** | `S2 → S3 → S4 →〔教师复核〕→ S6`，`S5` 横向贯穿全链 |
| **3 复核** | ❌ 不走 | `读入既有 ReviewResult → S7 入口 B 解释回放 → 无后置`（**只读**，无编排） |

> 所以：**本层描述的是「一条报告如何被评阅完」**，不是「Expert 能做哪几件事」——
> 后者由 `../skills/S0-task-router.md`（路由）回答。

## 四、完成判据对照（对应《步骤路径规划书》1.4）

| 规划书步骤 | 完成判据 | 本轮证据 |
|---|---|---|
| **1.4.1 五 Agent 编排规格** | **每环的输入、输出、置信度、证据引用齐备** | `W1` 为五环各设**四栏**（输入 / 输出 / 置信度 / 证据引用）逐环填满，并给出「环与环之间的交接物」表；每环另标出该环的**硬闸门**与其在契约中的落点（`steps[].agent` 五值 + `review` / `selfCheck` / `feedback` / `scores[]`） |
| **1.4.2 编排形态** | **两种形态都能跑通同一份报告** | `W2` 定义两种形态并给出**共同硬约束 6 条** + **选型判据**；等价性验收写死为 4 条可校验判据（`steps[]` 五值齐全 / `scores[]` 与评分点一一对应 / `totalScore`+`total` 一致 / 指纹差异可逐项归因）。⚠️ **两种形态的实跑对照须在平台侧对话完成**（AI 在对话侧运行），本工作区只保证规格齐备与产物形状可校验——该限制已在 `W2` §四 显式标注 |
| **1.4.3 失败处理** | **失败不中断全流程，有明确状态标记** | `W3` 给出三条原则（F1 失败不中断整链 / F2 重试只改结构不改判断 / F3 限定轮次仍败即停）、**8 个状态标记的闭环词汇表**、**逐环 12 类失败模式的处置表**、**回退边界表**（能退到哪 / 绝不能退到哪）、以及**六脚本退出码与 CI 判定口径**的映射表 |

## 五、本层不做什么

- **不做编排引擎**：不写调度代码、不引入工作流框架；编排是 Expert 在对话中的行为，由本层规格约束
- **不替代 Skills**：方法论在 `../skills/`，本层只规定**顺序、交接与失败路径**
- **不做时间规划**：形态选型只看「报告特征 / 分工 / 是否需要过程可见」，**不含任何工期估算**（项目既定口径）
- **不碰教师终判**：五环产出的是**建议态**；生效态的闸门在教师（`reviewMeta.status = draft → confirmed`）
