# 02 · 工作流程

> 技能解决「能不能做」，流程解决「按什么顺序做、在哪一步设闸」。
> 本文件给出六条已跑的流程；每条都标出**闸门位置**（不通过就停下）。

## 一、W1 · 五 Agent 流水线（评阅主链）

```
Parser → Evidence → Grader → Reviewer → Feedback
（解析）   （取证）     （判定）    （复核）     （评语）
```

每一环的输出都带**置信度与证据引用**，下一环只消费上一环的结构化产物，不做越级推断。
落点：`backend/autograder-expert/agents/workflow/W1-five-agent-pipeline.md`。

## 三、W3 · 失败与重试

统一退出码把「失败」分级，避免把「不适用」误读成「降级」：

- `0` 正常 ｜ `1` 可继续需注意 ｜ `2` 输入不可读或非法 ｜ `3` 降级（CI 视为不通过）
- T5 专用：`errors` 非空 → 退 1（即使同时有 `skipped`），但 `skipped` 必须逐条出现在输出里
- `--kind rubric` 只跑前三项 —— **不适用 ≠ 降级**，不得记进 `skipped`

落点：`agents/workflow/W3-failure-and-retry.md`。

## 五、专家包装配链（交付物一）

```
build_expert.py  →  validate_expert.py  →  register_expert.py
（按清单装配）       （官方校验，有 error 不能注册）  （写入 marketplace.json）
```

- **映射唯一真源** = `packaging/expert.manifest.json`：改映射改它，**不要改脚本**
- 装配器铁律：**绝不做破坏性动作**。早期「先整体删目录再写入」被宿主安全闸打断在半途把包打坏；
  现为 `stale_items()` 只报告不删除，要删须显式 `--prune`

## 六、docx 修订链（可复用的文档工程流程）

```
① docx → md（docx2md.py，调 T1 取 blocks 再映射回标题与表格）
② 改 md（逐条套用修订，直接产出新版）
③ md → docx（make_docx.py：create_doc → doc_insert_markdown → save_file）
④ 验证（两步缺一不可）
```

**验证为什么是两步**：先回读新 docx 比对「应存在的 / 应清除的 / 应保留的 / 原稿未被动过」，
再**逐块比对新旧 `blocks`**。判据是「块数与标题数不变、差异块数恰好等于预期改动处数」——
这是「整文重生成无连带变化」的唯一硬证据，只看 md 差异不足以收工。

## 七、对话归档链（交付物三）

```
scan_sessions.py  →  export_conversations.py  →  documents/dev_log/
（盘出未索引会话）    （逐字导出 + 完整性断言）      （README + 索引 + 逐字转录）
```

- 归档口径：用户/助手文本**逐字保留**；工具调用压一行；工具返回正文与推理过程剔除
- **必须带完整性断言**：磁盘上每个会话文件都要在登记表内
- 计数口径统一为**渲染行数**；未回报结果的调用单列「另有 N 次调用无结果回报」
- 开工惯例：先扫会话目录，把**未索引的会话补录**进总纲索引；索引行与日志编号**同一轮内一起登记**

## 八、提交与协作流程（Trunk-Based + PR 门禁）

```
① Issue 立项 → ② 从最新 main 切短分支 → ③ 开发自测 → ④ 提 PR → ⑤ Review + CI → ⑥ Squash 合并 → ⑦ 删分支
```

- 分支命名：`feat/` `fix/` `docs/` `chore/`，生命周期 ≤ 2 天
- 提交信息：Conventional Commits，一条只做一件事，可独立 revert
- 红线：main 禁 force push；`.env` / `node_modules` / 构建产物 / 缓存目录不入库；大文件走 Release Assets
- 冻结期：切 `release/<版本>` 分支，修复走 cherry-pick，最后打 tag

## 九、每轮对话的收尾动作（固定四步）

1. **释放文件占用** —— 结束本轮拉起的进程，否则用户改不了自己的文件
2. **追加工作区记忆** —— 日志 append-only；状态性变化同步进长期记忆
3. **同步项目总纲** —— 跨对话的唯一对齐入口，非冻结区自行维护、每次说明改了什么
4. **关联文档同步** —— 该项目实践中，交付物一变，README、契约说明、对话索引往往同时失真，
   需一并核对（2026-09-26 曾专项做过一轮「一致性修正」，一次修掉 6 处过时表述）
