# AutoGrader · 口径变更说明（v1.0 → v1.1）

> **用途**：逐条记录《步骤路径规划书》与《项目目标定义书》从 v1.0 到 v1.1 的差异、原因与**未改项**。
> **配套交付**：本说明与两份 v1.1 同批提交；两份 **v1.0 原件原样存档**。
> **生成依据**：对 v1.0 / v1.1 做**逐段差异比对**得出（不是凭记忆复述）。
> 段数对照：规划书 v1.0 → v1.1 为 50 → 59 段；目标定义书为 111 → 112 段。

---

## 一、版本策略

| 文件 | 角色 |
|---|---|
| `AutoGrader 步骤路径规划书_v1.0.docx` | **原样存档**：立项当日的原始判断，保留「人在时间压力下做取舍」的痕迹 |
| `AutoGrader 步骤路径规划书_v1.1.docx` | 修订版：按后续已确认口径更新表述 |
| `AutoGrader 项目目标定义书_v1.0.docx` | **原样存档**（同上） |
| `AutoGrader 项目目标定义书_v1.1.docx` | 修订版 |
| `AutoGrader 口径变更说明.docx` | 本文件：两版差异的逐条依据 |

**为什么两份都交**：本赛事把「禁止使用 AI 生成完整方案后直接提交（AI 是工具，不是替代者）」
写进合规红线，并要求提交对话记录。**「立项初稿 → 多轮修订稿」本身就是该红线的过程证据**；
而 v1.1 让评委不必在过期口径里自行辨真伪。

## 二、步骤路径规划书：v1.0 → v1.1

| # | 位置 | v1.0 原表述 | v1.1 新表述 | 变更原因 |
|---|---|---|---|---|
| 1 | 版本行 | `版本：v1.0` | `版本：v1.1` + 版本说明段 | 版本策略 |
| 2 | `1.1.3` 完成判据 | 「按 Prompt 口径**手算**与产物一致」 | 「**由 T4 确定性计算器产出**，且与 T5 的 `total.recompute` 复算值相等（不接受手算）」 | **判据与纪律对立**：`SYSTEM_PROMPT` §3.3 写死「所有数字必须由 T4 产出，不接受口算」，而原判据要求手算 |
| 3 | `1.2 Skills 层` | 5 项：报告解析 / Rubric 模板 / 证据取证 / 契约组装 / 评语写作 | **8 项 S0–S7**（任务路由 / Rubric 构建 / 报告解析 / 证据取证与判定 / 总分计算 / 装配自检 / 评语生成 / 复核与解释） | 技能层已定稿为 8 项；旧表**缺 S0 / S4 / S7**，并把 S4 与 S5 混成「契约组装」 |
| 4 | `1.3 Tools 层` | 4 项：文件解析 / 确定性核查器 / 契约校验器 / 样例检索 | **6 项 T1–T6**（文档解析器 / 客观核查器 / 引用解析器 / 确定性计算器 / 契约校验器 / 资产库） | 工具层已落地 6 项；旧表缺「引用解析器」与「确定性计算器」；且「样例检索」实为 T6 资产库（管四类资产，`rubric` 可读可写） |
| 5 | `1.3.3` 完成判据 | 「**三项**校验可独立运行、可单独报错」 | 「**六项检查**可独立运行、可单独报错」 | 契约冻结后 T5 实际执行六项：schema 结构 / 权重和 / 档位 / 证据与引用 / 总分复算 / 指纹复算 |
| 6 | `1.3.2` 完成判据 | 「输出与 Web 端核查器完全一致」（无限定） | 加限定「**待交付物二建立后校验**」 | 本工作区尚无 Web 端，该判据**当前无对照物**，不加限定会被误认为已验证 |
| 7 | `1.3.1` 输入与判据 | 「docx / pdf / md」「三类输入均可解析」 | 「**docx / pdf / md / txt**」+「**PDF 为保守文字层抽取，使用时须标注局限**」 | 实际支持四类；且 PDF 抽取不保证段落顺序与完整度，工具自身会输出局限警告 |
| 8 | 路径一开头 | 无 | **新增 `1.0 三模式总览`**（生产组：1 建标 / 2 评阅；消费组：3 复核） | 技能层与总纲已按三模式组织，规划书缺这一层会让读者看不出 S0 的作用 |
| 9 | 路径一末尾 | 无 | **新增 `1.7 打包与平台合规映射`**（6 条平台硬约束 + 完成判据） | 五件套到「平台能识别的专家包」还有一跳：平台**不存在「开发者注册工具」通道**、`tools/` 不是平台落点、Skill 须目录化含 `SKILL.md`、`agent.md` 禁写 `tools:` 字段、专家包有固定市场落点。缺这一跳整件事装不上 |
| 10 | `0.1` 行 | 「Zod schema + 契约说明文档」「通过 **zod** 校验」 | 「JSON Schema（`contract/`）+ 契约说明文档（`docs/contract.md`）」「通过**契约**校验」 | 事实性修正：冻结产物是 JSON Schema；判据由前端契约与工具链**双端**共同满足 |
| 11 | `0.3` 行 | 产物「计算函数 + 口径说明」 | 产物加「指纹实现（**Python / JS 双侧**）」，判据加「含**跨语言一致**」 | 事实性修正：指纹算法两侧实现，跨语言复算一致是硬要求 |
