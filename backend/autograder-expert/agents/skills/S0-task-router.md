# S0 · 任务识别与路由

| 项 | 内容 |
|---|---|
| Skill ID | S0 |
| 所属 | 前置 · **三模式**的唯一入口 |
| 对内 Agent | —（编排级，不对应单个 Agent） |
| 对外名称 | —（不作为独立步骤暴露给教师） |
| 依赖 Tool | — |

## 目标

判断教师本次要做什么，路由到三种模式之一；模式取值即契约的 taskType，一一对应、不得另造别名。

| 模式 | `taskType` | 教师意图 |
|---|---|---|
| 1 建标 | `rubric-build` | 建立 / 修改评分标准（Rubric） |
| 2 评阅 | `review` | 评阅实验报告（判分、出评语） |
| 3 复核 | `replay` | 回看 / 解释一份**已存在的**评阅结果（只读） |

杜绝用错流程；尤其杜绝把「复核」当成「重新评阅」。

## 输入

- 教师的自然语言输入
- 是否附带报告文件
- 是否附带或指向已保存的 Rubric
- 是否附带或指向**已存在的 `ReviewResult`**（模式 3 的必要条件）

## 输出

- 任务类型标记：`taskType` 取 `rubric-build` / `review` / `replay` 之一，并给出对应中文模式名
- 缺件清单，例如「判为 `review`，但未提供 Rubric」「判为 `review`，但未提供报告文件」
  「判为 `replay`，但未提供既有 `ReviewResult`」

## 执行规则

1. **只识别、不执行**——本 Skill 不产出任何评阅内容。
2. 意图不明时**只问一句**要哪一种模式，不猜、不代选。
3. 判为 `review` 但缺 Rubric 时，回复「先创建评分标准，或从样板库选一个」，
   **不得自行生成一份 Rubric 顶上**。
4. 判为 `review` 但缺报告文件时，不进入 S2。
5. 判为 `replay` 但缺既有 `ReviewResult` 时，**不得拿报告重算一遍冒充复核**——
   应说明「复核只回放既有结果」，并让教师在「改为评阅（`review`）」与「先提供既有结果」之间二选一。
6. 出现「帮我改进这份报告」这类学生视角的请求时，判为越界，明确拒绝并说明
   本 Expert 面向教师评阅。

## 常见失败场景

- 把「帮我看看这份报告」误判为 `rubric-build`。
- 把「这份为什么是这个分」误判为 `review`——**已有结果时应走 `replay`**；
  重算会让同一份报告出现两个互相矛盾的总分，破坏「同一份报告只有一条评阅链」。
- 把「帮我改进这份报告」当成「评阅这份报告」——改进是学生的事，不在本 Expert 职责范围内。
- 在缺 Rubric 的情况下自作主张生成一套标准，破坏「评分标准由教师定义」这条边界。

## 依赖关系

- 前置：无
- 后置：`rubric-build` → S1；`review` → S2；`replay` → S7（入口 B）
- 被三模式共同依赖（生产组 1 / 2 决定分数，消费组 3 只读不改判定）
