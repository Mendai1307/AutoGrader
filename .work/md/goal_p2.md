
# 四、项目目标定义

> **关于本章引用的页面、脚本与文档路径**：除 `contract/`（契约层）与 `docs/contract.md` 以外，
> 本章列出的 `/trace`、`/eval`、`/grade`、`/report/[id]`、`docs/testing.md`、`docs/learnbuddy-usage.md`、
> `conversations/` 等**均为 v0.1 已有资产**（在同级目录 `../AutoGrader`）。
> 本项目（rebirth）侧**尚未移植或重建**，因此本章证据清单中的这些路径**均须按「待重建 / 待移植」理解**。

## 4.0 总目标

**把 AutoGrader 做成「一个由 LearnBuddy 专家智能体真实驱动的计算机专业实验报告智能评阅系统」——

教师用自然语言定义评分点，智能体完成多模态解析 → 逐项证据核查 → 二次复核 → 成绩与评语生成，

产出可追溯、可复现、可评测的评阅结果；并以在线 Web 平台承载产品化界面与完整证据链，

形成「专家智能体（能力本体）+ Web Demo（产品形态）」双形态交付。**

一句话版本（对内对齐用）：

AI 跑在 LearnBuddy 里，产品放在浏览器里，证据留在仓库和对话记录里。

## 4.1 技术创新性（30 分）

目标：让"AI 评阅"从一次模型调用升级为一套可检验的评阅工艺。

| # | 关键举措（技术主张） | 为什么要这么做（评审视角） |
|---|---|---|
| T1 | 五 Agent 评阅流水线：Parser → Evidence → Grader → Reviewer → Feedback，逐环输出置信度与原文证据引用 | 直接回答"和直接问大模型有什么区别"——区别在于过程可见 |
| T2 | 契约驱动闭环：一份 ReviewResult 契约同时约束智能体输出格式、前端类型、仓库数据 | 三处同源，杜绝"演示数据 vs 真实数据"的质疑 |
| T3 | 证据强制回链：无证据不得高置信，违反即契约校验失败 | 把"AI 不能瞎说"从口号变成可执行的校验规则 |
| T4 | Compile-time AI 范式：AI 推理前移到开发时，运行时零 AI 调用 | 在"平台唯一 + 要在线链接"的夹缝中给出的原创解法 |
| T5 | AI vs 教师金标准一致性评测：逐项命中率、总分 MAE、置信度校准 | 把评委必问的"AI 靠不靠谱"变成一页数据结论（v0.1 已得 MAE 3.05，并主动披露差档 8.00） |

验收标准

[ ] 五 Agent 流水线的每一环，都能在 /trace 页看到该环的输入、输出与置信度变化

[ ] 任意一份 ReviewResult JSON 都通过**双端校验**：前端契约校验 + 工具链 **六项检查**（schema 结构 / 权重和 / 档位模型 / 证据与引用 / 总分复算 / 指纹复算）

[ ] /eval 页展示 AI vs 金标准的量化一致性，且指标可由页面上的原始数据复算

[ ] 至少一处"主动披露局限"（如差档 MAE 偏高），证明评测不是自吹

证据清单：/trace 溯源页 · /eval 评测页 · docs/contract.md · docs/testing.md（后三者中除 `docs/contract.md` 外均**待重建 / 待移植**）

| # | 关键举措 | 验收口径 |

## 4.3 AI 工具使用（25 分）—— 本阶段最高性价比

目标：让 LearnBuddy 的使用深度可验证，而不是"我们用了 AI"。

| # | 关键举措 | 说明 |
|---|---|---|
| A1 | 构建形态 A：LearnBuddy「实验报告评阅专家」专家智能体（本次重生核心） | 注入评分方法论、Rubric 模板、样例库、固定输出契约；教师可直接对话、上传报告获得真实评阅。**确定性能力以 CLI 脚本承载**（平台不提供开发者注册工具的通道），由平台内置命令行工具调起 |
| A2 | 对话记录即核心资产：一条主线对话 + 每份报告一条 + 每个关键决策一条 | 迭代过程完整保留，不删历史；索引写入仓库 |
| A3 | 真实溯源字段：每条结果 JSON 带真实 sourceConversationId + sourceTurnId | 评委可顺着 ID 找到那一轮对话 |
| A4 | 网页 ↔ 智能体双向耦合：Web 端深链唤起（learnbuddy://task?action=start&prompt=...） | 把"构建期固化的结果"升级为"现场可交互复现"，是本维度最强的加分动作 |

验收标准

[ ] 仓库内对话记录索引 ≥ 10 条，条目与结果 JSON 一一对应

[ ] /grade 或 /report/[id] 页上的"用评阅专家重跑"按钮，点击可拉起 LearnBuddy 并预填上下文

证据清单：专家智能体 · conversations/ 对话归档 · 深链演示 · docs/learnbuddy-usage.md（**待重建 / 待移植**）

风险提示：A4 依赖的是客户端自定义协议（逆向发现、非官方开放 API）。定位为增强项，不作为核心闭环的唯一起点；必须在 PPT 中把合规表述写清——它是操作系统级的用户主动唤起，不是 API 调用、不绕过授权、不自动执行。

## 6.2 关键契约备忘（实施时极易踩坑）

总分口径必须写成：总分 = Σ (score / maxScore) × weight，而不是 Σ (score × weight / 100)。

原因：各评分点的 maxScore 是教师自定标度（5 / 10 / 15 / 20 不等），标度大小不影响占比，占比只由 weight 决定。若 Prompt 中不显式写清口径与权重序列（5/12/5/7/20/10/11/13/7/5/3/2），模型极易按错误口径算总分，产物会在指纹校验环节失败。

另两条同级的口径纪律（与总分口径同属"写死"）：

- 待复核项**不计入**总分求和、**不做归一化**；总分因此是**部分分（下界）**，必须携带未计入权重合计
- 指纹算法的自指字段（结果指纹本身）在计算前必须**置为空串且键存在**，否则生产者与校验者两侧复算不相等

# 七、一句话结论

交付的不是"一个能调大模型的网站"，而是"一个由 LearnBuddy 专家智能体真实驱动的评阅系统，以及它的产品化界面与完整证据链"。

四个维度其实在问同一件事：你说的每一句话，能不能被验证。 技术创新性问"过程能不能被看见"，工程完整性问"结果能不能被复算"，AI 工具使用问"对话能不能被追溯"，用户体验问"评委能不能自己上手验证"。把"可追溯"做到极致，四个维度一起涨。
