### P1 · 正确性（5 项）

**P1-7｜T3 引用解析器对入参形状不符**静默放行**（本审查发现的最严重行为缺陷）**
- 实测：候选文件顶层键写成 `candidates`（而非 `items`）→ `summary={total:0, valid:0, rejected:0}`，**exit 0 = "全部有效"**。
- 为什么严重：T3 是「证据不得改写、不得拼接、不得用类似表述冒充引用」这条纪律的**唯一硬闸门**（T3 规格原文：「没有本工具，这条纪律只能写在 Prompt 里靠模型自觉；有了它，篡改引用会直接校验失败」）。入参形状一偏，闸门**静默全过**——这条纪律实际上就不成立了，而且是**零报错地**不成立。
- 根因：T3 / T4 / T5 三份规格的「输入」一节**均未写明入参顶层包裹键是 `items`**。按规格字面实现（裸数组或其它键名）就会踩中。
- 建议动作：① 三份规格补写完整入参样例；② 脚本对形状不符改为 exit 2 + 结构化报错（禁止静默返回空集）。

**P1-8｜T4 确定性计算器对入参形状不符崩溃 / 空输入误报成功**
- 实测 A：`--items` 指向裸 JSON 数组 → 未捕获 `AttributeError`（`'list' object has no attribute 'get'`）→ Python traceback 落标准错误，退出码 1。规格要求 `2` = 输入不可读或非法 → **结构化报错**。
- 实测 B：`--items` 指向 `{}` → **exit 0**、`total 0.0`、`isPartial false`、`gradeNote="已计入权重合计 0.0 ≠ 100"`。即「完全没有输入」被报成「正常」。
- 后果：S4 是总分唯一出口。上游一旦给错形状，得到的要么是崩溃，要么是"总分为 0 且无异常"——**后者会被当成合法评阅结果**。
- 与 P1-7 同源，建议一并修。

**P1-9｜T5 退出码优先级与规格不符**
- 规格原文：「只要有 `skipped` 项，退出码为 **3**」。实现为 `if errs: return 1; if skipped: return 3` → 二者并存时返回 1，**降级信号被普通错误掩盖**。
- 影响：CI 中 1 与 3 都判不通过，故无实际放行风险；但失去「契约未冻结」这一区分度，无法从退出码看出"结果不可信是因为依赖缺失"。

**P1-10｜T2 对非法报告对象返回 exit 1 而非 2**
- 实测：`--report` 指向裸数组 → exit 1。规格为「2 = 规则集非法或报告对象不可读 → 结构化报错」。当前会被下游读成「部分规则未覆盖」。

**P1-11｜`SYSTEM_PROMPT.md` §2 未并入四模式**
- 文件头自标待修订项：「四模式设计（建标 / 评阅 / 复核 / 教学分析）确定后，本文件 §2 工作流程与 §7 输出格式需同步调整」。四模式已于 C-016 定稿，但 §2 至今**只有流程 A / 流程 B**，无模式 3（复核，只读回放）与模式 4（教学分析，本期不做）的路由与边界；§1.1「你必须做的」六条也未含模式 3 的只读回放。
- 与 `skills/README.md` 第一节（已改为「四模式 + 生产组 / 消费组」）**口径不一致**。
- 建议动作：§2 第 0 步「任务识别」改为四模式路由；补模式 3 的只读约束与模式 4 的「本期不做」声明。

1. **规格层扎实、实现层有洞**：Skills 8 项 / Tools 6 项规格自洽且互相引用规范（口径只在 S4 定义一次），6 个脚本自测全通过、无第三方依赖、T4/T5 共用实现——这部分的工程质量高于多数参赛队同期水平。
