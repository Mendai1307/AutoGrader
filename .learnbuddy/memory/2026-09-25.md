### 本轮核心结论（长期有效，后续设计须遵守）

**教师工作流五环节**：定标准·布置 → 收件·形式审查 → 逐份评阅 → 风险排查 → 反馈·收尾。
- 耗时黑洞在「逐份评阅」，但其瓶颈不是"判断难"而是"**找证据难**"——判断几秒，翻找几分钟
- 「反馈·收尾」内部混合：生成任务（可交）+ 沟通任务（不可交），二者被压在一起，
  导致教师整段缩水成套话，用牺牲反馈质量换时间
- 起点其实是「把评分标准说出来」，而现实中常常没真正完成 → **最大价值点：标准外化 = 教学资产**

**问题拆解 P1–P8**：P1 标准留在脑中 / P2 形式清点 / P3 定位证据 / P4 逐点判定 /
P5 分数锚点漂移 / P6 评语可执行性 / P7 雷同线索 / P8 共性问题与教学改进

**三条判据线**：可判定性 / 出错代价 / 责任归属（**不按"难易"分**——难易是 AI 自己的能力问题，
不是该不该交出去的理由）

**三层边界**：
- 第一层 AI 主导教师抽查：形式与结构核查、结构化抽取、客观指标复算、证据定位摘录
- 第二层 人机协同 AI 初判教师终判：逐点建议分与档位、证据充分性初判（带置信度）、
  评语初稿、雷同线索 → 教师认定
- 第三层 教师独有：评分点定义/权重/价值取向、诚信认定与处分、最终分数与签字、
  特殊情况裁量与学生沟通申诉
- **第二层是唯一"AI 可能理直气壮地错"的地方** → 后续 Prompt 的证据纪律主要守这里

**六条陷阱（Prompt 里须写成硬拒绝）**：AI 直接出最终成绩 / 认定抄袭 / 判断"学生是否真的理解" /
决定评分点价值取向 / 写沟通性语言 / 无证据给高置信度。
其中最值得用于叙事的一条：**"报告看起来对"与"真的对"的落差**——AI 易被"写得漂亮但做错了"骗到，
而这恰是教师判断最不可替代之处。

**三条定位判断**：
1. 不是"AI 打分器"，是"**教师注意力的分配器**"
2. AI 的不可替代性不在"更准"，在"**不漂移 + 可追溯 + 可规模化**" →
   **Evaluation 层主指标应改为「一致性」与「置信度校准度」**，"离金标准有多近"降为次要指标
3. 结论应按「**出错代价**」分级而非按难度分级 → 契约可能需要
   "结论允许被用来做什么"的等级（可直接采信 / 需教师复核 / 仅供线索）

> ⚠️ 判断 2、3 会触碰**已冻结的 `ReviewResult` 契约**，本轮**只提出未改动**，待用户决策。

### 三条最要紧的边界线

1. **评分标准：专家负责「编码」，教师负责「赋值」**。样板是起点不是标准——
   措辞必须守住，否则会被读成"AI 制定评分标准"（评审必追问点）
2. **证据：可以说「未找到」，不能说「不存在」** —— 必须进契约硬校验
3. **成绩：可以「算分」，不能「给分」** —— 区别在签字权

### 四条跨维度铁律

- **L1 未知优于否定**（适用于解析、证据、评分三处）
- **L2 建议态优于生效态**（契约需可区分状态标记）
- **L3 计算可做，认定不可**（计算＝复算/统计/相似度/结构抽取；认定＝诚信/是否理解/特殊情况）
- **L4 不一致必须留痕**（教师改写差异是评测数据，不是污点）

### ⚠️ 我在第 6 轮的一处错误表述（已当场撤回，务必记住）

第 6 轮我说「归一化会改动冻结公式的**分母**（分母从 100 变成已计入项权重和）」——
**这句话不成立。冻结公式里没有分母。**
- 真实情况：逐项 `(score/maxScore) ∈ [0,1]` → 乘 weight 后 `∈ [0, weight_i]` → 求和 `∈ [0, Σweight]`
- `Σweight = 100`（5+12+5+7+20+10+11+13+7+5+3+2）→ 0–100 是**权重和约定推出来的量纲**，
  不是任何一步除法算出来的
- 错误诱因（推测）：v1.0 文档同时否定过错误口径 `Σ (score × weight / 100)`，那里有显式的 `/100`，
  我把它误带进了正确口径

**教训 / 通用纪律：不得把"结果性质"（结果落在某区间）表述成"公式结构"（公式里有某运算）。
引用冻结公式时，只描述公式里字面存在的东西。**

### 但该确认点背后的真问题是成立的（已验算）

链条：Q6「待复核项先不计入」→ 改变 **求和范围** → 上界变为 `Σ已计入 weight`
→ 若待复核项权重合计 `W_r > 0`，总分上限 `= 100 − W_r < 100` → **该数不再是百分制成绩**

算例（权重 40/35/25，得分率 0.80/0.60/1.00）：

| 复核进度 | 部分分 Σ已计入 | 归一化 ÷已计入权重和×100 |
|---|---|---|
| 1 项 | 32 | 80.0 |
| 2 项 | 53 | **70.7（回撤）** |
| 3 项 | 78 | 78.0 |

- 两者**终值相同**，差异只在过程
- 部分分**单调不减**（下界抬升）；归一化**会回撤**（80 → 70.7 → 78）
- **决定性理由**：归一化会让"教师认真复核"在界面上表现为"分数往下掉"

**推荐取向**：部分分（下界）——冻结公式一个字不改，只是 Σ 范围变小 + 附加一个
「未计入权重合计 W_r」字段；UI 显示为"暂定 X（未含待复核项，上限 100−W_r）"。
**待用户一句话确认。**

### 三、行为与安全边界（决定"一键"到底是几键）

- 深链只**预填草稿**，评委必须自己点发送 → 实际是"一键拉起 + 一次确认"

- 协议名不可探测：LearnBuddy 品牌包注册 `learnbuddy://`，WorkBuddy 品牌包是 `workbuddy://`，网页侧无从判断

### 四、本轮结论（要点）

**推荐工程解**：仓库内直接放**已合规的专家包**（而不是让评委机器上的智能体"重新生成"），
prompt 只要求「克隆/复制到专家目录 + 跑 register 脚本」——确定性高、无输出漂移。
